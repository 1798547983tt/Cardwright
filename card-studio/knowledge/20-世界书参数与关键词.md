# 20 · 世界书参数与关键词

> 适用版本：SillyTavern 1.19.0 ｜ 核对日期：2026-09-17 ｜ 对应分区：世界书各分区、拼装
>
> 核对来源：SillyTavern 源码 `public/scripts/world-info.js`（`world_info_position`、`world_info_logic`、`newWorldInfoEntryDefinition`、`convertCharacterBook`）。顺序方向与聊天世界书已于 2026-09-18 在真实酒馆里验证（SillyTavern 1.19.0 + 酒馆助手 4.9.5），见文末。

## 1 位置（position）

`position` 是数字枚举：

| 值 | 含义 |
| --- | --- |
| 0 | 角色定义前 |
| 1 | 角色定义后（酒馆默认） |
| 2 | 作者注释顶部 |
| 3 | 作者注释底部 |
| 4 | @深度（配合 `depth`） |
| 5 | 示例消息前 |
| 6 | 示例消息后 |
| 7 | Outlet |

@深度 的 `depth` 表示插在倒数第几条消息之前：`depth = 0` 最靠近对话末端。正文格式用 @深度 0，剧情条目用 @深度 4。

## 2 顺序（order）

制卡工坊的顺序表：

| 段 | 触发 | 位置 | 顺序 |
| --- | --- | --- | --- |
| 正文格式 | 常驻 | @深度 0 | 0 |
| 叙事规则 | 常驻 | 角色定义前 | 1–9 |
| 人物总览、地点总览 | 常驻 | 角色定义前 | 10–14 |
| 标题剧情索引 | 常驻 | 角色定义前 | 15–19 |
| 世界段设定 | 常驻 | 角色定义前 | 20–49 |
| 核心设定 | 常驻（可附关键词） | 角色定义前 | 50 |
| 其余设定 | 关键词 | 角色定义前 | 51–99 |
| 人物 | 关键词 | 角色定义前 | 100 |
| 玩家设定（聊天世界书） | 常驻 | 角色定义前 | 100 |
| 剧情 | 关键词 | @深度 4 | 300 起，按时间递增 |
| 初始变量 [initvar] | 关闭 | 角色定义前 | 1002 |
| 变量列表 / 变量规则 / 变量输出格式 | 常驻 | 角色定义前 | 9994 / 9995 / 9996 |

原则：越基础的条目顺序数字越小；越要求模型严格执行的条目越靠近最新消息（顺序数字更大，或改用 @深度）。

## 3 递归与统一参数

- `excludeRecursion`（不可被递归触发）与 `preventRecursion`（阻止进一步递归）在本工坊里一律开启。世界书条目之间互相触发会让上下文迅速膨胀，且难以预料。
- `keysecondary` 留空，`selectiveLogic` 为 0（AND ANY），`probability` 为 100。工坊不用概率触发：卡的行为要可复现。
- `constant` 为真表示常驻：每次都注入，占固定预算。
- `disable` 为真表示关闭：条目还在卡里，但不注入。分歧组里的备用条目就是这样存放的。

## 4 关键词

- 关键词按**正则**处理（酒馆导出卡时固定写 `use_regex: true`），所以 `.`、`(`、`|` 这类字符有特殊含义。人名地名里出现它们时要留意。
- 数量规则：设定类 2–3 个精准词；人物 5 个以内（本名 + 常用译名或昵称）；剧情为篇章名加该条涉及的每一个完整日期。
- **禁止共用称号**：把「九神将」这类多人共用的头衔写成关键词，一出现就会同时触发一串人物条目。参考卡 Re0 里「九神将」被 11 条人物条目共用，正是这个问题。
- 撞词检查：两条启用条目共用同一个关键词时，拼装检查给警告。剧情条目共用日期是正常的（同一天的事件分布在多条里），检查会跳过这种情况。

## 5 多个世界书同时生效

注入次序：聊天世界书 → Persona 世界书 → 角色世界书与全局世界书。后两者之间的先后由全局策略决定，默认按统一排序。

创角页把玩家设定写进**聊天世界书**（ADR 0012），这样每个存档一份，不污染角色主世界书。酒馆版本不支持聊天世界书时退回写入主世界书，并在创角页提示用户。

## 6 常驻预算

常驻条目每轮都注入，是固定开销。写卡时按这个顺序控制：

1. 先算常驻总字数（拼装检查会报出字数和估算 Token）。
2. 超预算时，先把能按关键词触发的内容挪成触发条目。
3. 仍然超，就砍支线内容，并在设计书的「不做清单」里记一笔。

估算方式：中文约 0.7 Token 一个字，其余按四个字符一个 Token。这是估算，真实数字取决于模型的分词器。

## 7 在真实酒馆里确认过的事

2026-09-18 用 SillyTavern 1.19.0 + 酒馆助手 4.9.5 + MVU-offline 1.0.1 实测：导入制卡工坊导出的验证卡，让本机假模型记下它收到的每一份提示词，直接看条目落在哪里。证据在 `artifacts/card-studio-0.8/stage-4/`。

- **顺序方向**：同一个插入位置里，**顺序值小的在前，大的在后**，也就是越大越靠近最新消息。实测六条都在「角色定义前」的常驻条目，顺序 2 / 10 / 50 / 100 / 9995 / 9996，在模型收到的提示词里正好依次排列。
- **聊天世界书**：酒馆助手的 `getOrCreateChatWorldbook('current', 书名)` 可用，建好即绑定到当前聊天。它的条目和角色世界书的条目**在同一插入位置按顺序值混排**：聊天世界书里顺序 100 的「玩家设定」排在角色世界书顺序 100 的条目之后、顺序 9995 的条目之前。所以创角页写入的玩家设定用顺序 100、角色定义前，会紧跟在人物条目后面。
- **@深度 与正则深度**：见 `30-正则与渲染管线.md` 第 3 节——正则的楼层限制只在楼层被渲染的那一刻判断。
