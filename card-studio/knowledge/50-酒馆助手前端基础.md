# 酒馆助手前端基础

| 适用版本 | 核对日期 | 核对方式 |
| --- | --- | --- |
| 酒馆助手（JS-Slash-Runner）v4.x | 2026-09-17 | 对照本地 ST 资料库与参考卡脚本 |
| 酒馆助手 4.9.5 + SillyTavern 1.19.0 | 2026-09-18 | 真实酒馆实测，并对照该版本自带的类型声明 `@types/` |

对应分区：正则各分区、脚本各分区。

## 1. 谁在执行这些代码

SillyTavern 本体不会执行角色卡里的任意 JS。执行的是**酒馆助手**扩展：它把卡里的代码放进 `<iframe>` 沙盒里跑，并把自己的接口以**全局函数**的形式注入进去——直接调用 `getVariables(...)`，不需要 import，也不写 `TavernHelper.` 前缀。

两种 iframe，性质不同：

| | 楼层 iframe（正则渲染出来的界面） | 脚本 iframe（脚本库里的脚本） |
| --- | --- | --- |
| 生命周期 | 随这一楼渲染而生，随重绘而毁 | 随卡或全局脚本运行，跨楼层存活 |
| 特有函数 | `getCurrentMessageId()` | `getScriptId()` |
| 常用变量作用域 | `{ type: 'message' }` | `{ type: 'script' }`、`{ type: 'chat' }` |

不同楼层的 iframe 之间不能直接访问彼此的 `window`，要通过变量、事件或接口分享来通信。

## 2. iframe 里已经有的东西

不用 import 就能用：`$`（jQuery）、`_`（lodash）、`z`（Zod 4）、`YAML`、`toastr`、`window.SillyTavern`、`window.TavernHelper`、`tavern_events`、`iframe_events`。

制卡工坊的工程规则：除 MVU 与 Zod 注册这两个固定件写死的地址外，不要再引入别的外部脚本、字体或图床。

## 3. 事件

```js
const stop = eventOn(tavern_events.MESSAGE_RECEIVED, handler);
// …
stop.stop();   // 需要提前取消时
```

- `eventOn` 持续监听，`eventOnce` 只响应一次，`eventMakeFirst` / `eventMakeLast` 调整顺序。
- 两套事件常量不要混用：`tavern_events.*` 是酒馆自身的事件名，`iframe_events.*` 带 `js_` 前缀，是 iframe 生命周期事件。
- **监听器要自己收好**：把 `eventOn` 的返回值放进一个 `disposers` 数组，组件销毁或聊天切换时逐个 `stop()`。虽然文档说 iframe 关闭时会自动卸载，但长期运行的脚本 iframe 不手动清理会累积，重复渲染时界面会叠加。

```js
const disposers = [];
disposers.push(eventOn(tavern_events.CHAT_CHANGED, redraw));
function dispose() { while (disposers.length) disposers.pop()?.stop?.(); }
```

## 4. 变量

```js
const vars = getVariables({ type: 'message', message_id: 'latest' });
insertOrAssignVariables({ ui: { collapsed: true } }, { type: 'chat' });
```

作用域 `type` 可选 `chat`（当前聊天，最常用的跨楼层载体）、`global`、`message`（单楼，支持 `'latest'` 与负数索引）、`script`、`preset`、`extension`。

- 读用 `getVariables`；整体替换用 `replaceVariables`；只改几个键用 `insertOrAssignVariables`；要避免竞态用 `updateVariablesWith`。
- 卡的剧情变量走 MVU（见 `40-MVU 变量与 Zod.md`），前端只读不写。界面自己的小状态（折叠、分页）可以写 `chat` 或 `message` 作用域，但不要塞进 MVU 的 `stat_data`。
- 世界书条目里可以用宏读变量：`{{get_chat_variable::路径}}`（JSON）、`{{format_chat_variable::路径}}`（YAML，模型更好读）。

> 待真机验证：`updateVariablesWith` / `insertVariables` / `deleteVariable` 的实际行为，以及 `getAllVariables` 的合并优先级。

## 5. 消息与界面

- `getCurrentMessageId()` 取当前楼层号，`getLastMessageId()` 取最后一楼——状态栏靠这两个判断「我是不是最新一楼」。
- `getChatMessages` / `setChatMessages` 读写消息内容；创角页把开场信息填进酒馆输入框时，操作的是主窗口的输入框元素。
- 世界书接口：`getCharWorldbookNames('current')`（取 `.primary`）、`getWorldbook`、`updateWorldbookWith`；聊天世界书用 `getChatWorldbookName('current')` 与 `getOrCreateChatWorldbook('current', name?)`。
- 生成接口 `generateRaw` 走用户当前的模型连接——创角页的「AI 帮写」只用它，卡里永远不要收 API Key。

**实测（酒馆助手 4.9.5）**：主窗口的 `window.TavernHelper` 上有 `getVariables`、`insertOrAssignVariables`、`replaceVariables`、`updateVariablesWith`、`waitGlobalInitialized`、`getLastMessageId`、`getCharWorldbookNames`、`getWorldbook`、`updateWorldbookWith`、`createWorldbookEntries`、`getChatWorldbookName`、`getOrCreateChatWorldbook`、`generateRaw`、`getChatMessages`、`setChatMessages`。`getCurrentMessageId`、`getScriptId`、`eventOn`、`eventOnce` 不在主窗口的对象上，只注入给 iframe（类型声明在 `@types/iframe/`）——所以这几个只能在前端界面和脚本里用。

参数形态以该版本自带的 `@types/function/*.d.ts` 为准，例如：

```js
const name = await getOrCreateChatWorldbook('current', '卡名 · 存档名');   // 建好即绑定到当前聊天
await createWorldbookEntries(name, [{
  name: '玩家设定', enabled: true,
  strategy: { type: 'constant' },
  position: { type: 'before_character_definition', order: 100 },
  content: '…',
}]);
```

世界书条目在酒馆助手里是它自己的形状（`strategy`、`position`、`recursion`、`effect`），不是酒馆世界书文件里的字段名。实测上面这段在 1.19.0 里能建出聊天世界书，并且条目按顺序值出现在提示词里（见 `20-世界书参数与关键词.md` 第 7 节）。

酒馆助手还会接管两件事：角色面板的「替换/更新」之后，它把新卡的内嵌世界书写回已绑定的同名世界书；导出角色卡之前，它先把当前世界书存一遍。

> 待真机验证：`generateRaw` 的参数与返回（本次冒烟没有调用它）。

## 6. 写前端的工程底线

- 一个正则的替换内容就是一个完整 HTML 文档：`<!DOCTYPE html>`、样式、结构、脚本都在里面。
- 纹理、边框、图标用 CSS/SVG 自己画；字体用系统字体栈；立绘与音乐只用用户给的链接；不要把大图以 base64 塞进替换内容（会把卡撑大、拖慢渲染）。
- 输出到页面的文本全部转义，不执行消息正文里的脚本。
- 手机宽度（375px）下单列可用，不横向滚动。
- 渲染范围要限制：状态栏只在最新一楼渲染，正文美化只渲染最近若干楼（见 `30-正则与渲染管线.md` 的深度过滤）。
- 自带错误面板：出错时显示步骤、错误信息和【复制报错】按钮，并给用户 F12 的排错步骤。
