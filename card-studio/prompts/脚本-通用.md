## 脚本通用规则

本节适用于脚本板块的每个分区。下面还有本分区的专用规则，两者冲突时以专用规则为准。

### 一个脚本就是两个文件

- `脚本/<序号>-<名称>.js`：脚本正文，由你写。
- `脚本/<序号>-<名称>.json`：脚本参数（`name`、`id`、`enabled`、`button`、`info` 等），由应用维护。你只在需要时改 `name` 和 `info`，其余字段不要动。

新建脚本调用工具 `card_new_component`，参数 `board` 填 `script`、`name` 填脚本名。它会建好这两个文件并把路径告诉你。不要自己编 `id`，也不要复制别人的参数文件。

工具：

- `card_new_component`：新建一个组件。
- `card_check`：跑一次拼装检查，读回错误、警告和常驻预算。交付前跑一次。

### 运行环境

- 脚本由酒馆助手（JS-Slash-Runner）在 iframe 里执行，每次进入聊天时运行一次。
- 全局可用：`$`（jQuery）、`_`（lodash）、`z`（Zod 4）、酒馆助手的接口（`getVariables`、`eventOn`、`tavern_events`、`getScriptId` 等），以及 `Mvu` 对象。
- 用到 MVU 数据前必须先 `await waitGlobalInitialized('Mvu')`，不要假设它已经就绪。
- 接口的确切名称和参数以知识库 `50-酒馆助手前端基础.md` 为准；那里没写的接口，先停下来说明，不要凭印象调用。

### 写法

- 用现代 ES 模块写法，顶层 `await` 可用。不引入构建步骤，不写 TypeScript。
- 外部依赖只允许固定件里已经写死的地址（见各分区）。其余一律自己实现，不要临时引入 CDN。
- 一个脚本只负责一件事，并在开头的注释里写明：它做什么、读哪些变量、写哪些变量、监听哪些事件。
- 监听器要能清理：在 `tavern_events.CHAT_CHANGED` 之类的事件上重新绑定前，先解绑旧的，避免重复渲染叠加。
- 不收集 API Key，不执行消息正文里的脚本，输出到界面的内容一律转义。

### 固定件原样使用

固定件由应用或参考文件提供，你原样使用，不要改写、不要「优化」：

- **MVU 脚本**：`content` 只有一行 `import 'https://testingcf.jsdelivr.net/gh/NLKASHEI/MVU-offline@v1.0.1/mvu_bundle_full.js'`；按钮里只保留「重新处理变量」「重试额外模型解析」可见。
- **Zod 结构脚本**：由应用从 `变量表.yaml` 生成，不要手写或改写；要改字段，改变量表再生成（见「脚本 · 变量结构」）。

### 顺序

脚本板块的三个分区有先后：**变量结构 → 世界书控制器 → 机制脚本**。缺少上游产物时停下来，请用户先去上游分区。

## 报错回路

每个脚本都要能自己说清出错在哪里：

- 用一个 `try/catch` 包住入口，出错时在控制台打印 `[卡名·脚本名] 出错：` 加上错误对象，并在界面上给出一句人话提示。
- 有界面的脚本（悬浮球、面板）自带错误面板：显示最后一条错误、出错的步骤名，以及一个【复制报错】按钮。
- 交付时附一段 F12 排错步骤：打开开发者工具 → Console → 筛选卡名 → 复制整段报错发回来。
