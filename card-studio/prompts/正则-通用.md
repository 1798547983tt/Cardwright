## 正则通用规则

本节适用于正则板块的每个分区。下面还有本分区的专用规则，两者冲突时以专用规则为准。

### 一条正则就是两个文件

- `正则/<序号>-<名称>.html`：替换内容，由你写。状态栏、正文美化、开局创角页这三类前端的替换内容是**一个完整的 HTML 文档**：从 `<!DOCTYPE html>` 写到 `</html>`，前后不留别的内容。
- `正则/<序号>-<名称>.json`：正则参数，由应用维护。你可以改的字段：`findRegex`、`placement`、`minDepth`、`maxDepth`、`disabled`、`promptOnly`；`id` 不要动。

### 前端围栏：你只写 HTML 文档，围栏由应用补

- 酒馆助手只把**代码块**里的文档渲染成 iframe。没有外面那层 ```` ```html ```` 围栏，脚本不跑、点不动，文档还会被当成消息正文净化（class 加 `custom-` 前缀、`:root` 里的变量失效、不认识的标签被删）。
- 这层围栏由应用在拼装、导出单件和本地预览时自动补上：开头 ```` ```html ````，结尾 `</html>` 加闭合围栏，和 Re0 卡的写法一致。**文件里不要自己写围栏**；已经带了的不会重复包。
- 变量更新回执这类内联替换内容（`<section>` + `<style>`，没有脚本）不是 HTML 文档，应用不给它加围栏，你也不要加。
- 拼装检查（`card_check`）核对围栏，下面几种都是错误（`frontend-fence`），会禁止导出：文档前后多了文字（应用没法补围栏）；内联回执被包进了围栏；围栏里的文档不以 `</html>` 结尾；不是完整文档却写了 `<script>`；文档里有单独一行三个反引号（会提前结束围栏）。

新建正则调用工具 `card_new_component`，参数 `board` 填 `regex`、`name` 填正则名。

工具：

- `card_new_component`：新建一个组件。
- `card_check`：跑一次拼装检查。它会编译 `findRegex`、核对 `placement`，用正文格式里的示例输出检查你的正则能不能命中，并对每个前端做围栏与前端质量检查（`frontend-` 开头）。交付前跑一次。

### 参数

- `findRegex` 写成 `/模式/标志` 的形式，和酒馆里一致。要匹配整块内容时用 `([\s\S]*?)` 而不是 `.*`。
- `placement`：`1` 用户消息、`2` AI 消息、`3` 斜杠命令、`5` 只改提示词、`6` 世界书。前端渲染一律用 `[2]`（创角页按分区说明可能用 `[1,2]`）。
- `promptOnly` 为 true 时只改发给模型的提示词，不改显示；只改显示的正则把它保持为 false。
- `markdownOnly` 保持 true，`runOnEdit` 保持 true。
- **渲染楼层**：状态栏只渲染最新一条 AI 回复；正文美化只渲染最近 10 楼（楼层数可在设计书里调整），更早的楼层由轻量正则去掉标签显示成纯文本。实测（SillyTavern 1.19.0）：`maxDepth` 只在楼层被渲染时判断——载入、重新载入聊天时生效，聊天进行中旧楼层不会被重画。所以正文美化用 `maxDepth` 就够（卡慢在载入长聊天）；状态栏在 `maxDepth: 0` 之外，还要在脚本里判断自己是不是最新一楼（见知识库 `60-状态栏与开局页.md`）。
- **不用 iframe 的替换内容**会被酒馆净化：class 加上 `custom-` 前缀（替换内容自己的 `<style>` 会跟着改写，照常写类名即可；别处的选择器要写 `.custom-…` 或用 `data-*` 属性），引号括起的文字被包进 `<q>`，不认识的标签被去掉、文字保留。详见知识库 `30-正则与渲染管线.md` 第 5 节。

### 前端写法

- 一个 HTML 文档写完：`<!DOCTYPE html>`、`<style>`、`<body>`、`<script>` 都在同一个文件里。
- 先读 `styles/README.md`，再读设计书「风格预设」一节点名的那一篇：把它的令牌表原样抄进 `:root`（令牌名不改，可以统一加卡名前缀），别处一律用 `var()` 取值。
- 做到 `styles/README.md` 的「必须做到」十条：令牌成套；主色、辅色、状态色三档分工；可点的东西有 `:hover`、`:active`、`:focus-visible`；至少一处克制的动效，并写 `@media (prefers-reduced-motion: reduce)`；空值显示「未知」或「—」；375px 单列、不横向滚动，点击区域不小于 32px；正文对比度不低于 4.5:1；系统字体栈，不用 Google Fonts；纹理、边框、图标用 CSS/SVG 自己画，立绘、头像、音乐只用设计书里给的链接，不把大图以 base64 塞进替换内容；自带错误面板。
- 质感向 Re0 卡看齐：圆角、渐变、阴影可以用，但每一处都有用途；状态变化有过渡；悬停、按下、聚焦、禁用四种样子写全。
- 交付前跑 `card_check`：`frontend-` 开头的错误（横向滚动、没有交互反馈、正文对比度不足、Google Fonts、大图 base64、围栏）必须清掉；警告（令牌不足、没有 @media、循环动画没照顾减少动画、主色用得太多）逐条改或在交付里说明理由。
- 输出到页面的文本一律转义，不执行消息正文里的脚本，不收集 API Key。
- 只读取变量、不写变量（创角页除外，见它自己的规则）。
- 事件监听器要能清理，重复渲染时不叠加。

### 与其他分区的边界

- 输出结构（标签、字段、枚举）属于世界书 · 正文格式；这里只负责把它渲染好。
- 变量字段属于脚本 · 变量结构；这里只读，不新增字段。
- 结构或字段不够用时停下来，回上游分区补，不要在正则里造新字段。

## 报错回路

每条前端正则都要自带错误面板：

- 用 `try/catch` 包住解析与渲染，出错时在页面上显示一块可读的错误区：写明出错的步骤（解析 / 渲染 / 读变量）、错误信息，以及一个【复制报错】按钮。
- 解析失败时**显示可读的原文**，不要空白，也不要补造内容。
- 控制台日志统一以 `[卡名·正则名]` 开头。
- 交付时附 F12 排错步骤：打开开发者工具 → Console → 筛选卡名 → 复制整段报错。
