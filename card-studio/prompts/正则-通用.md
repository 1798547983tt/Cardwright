## 正则通用规则

本节适用于正则板块的每个分区。下面还有本分区的专用规则，两者冲突时以专用规则为准。

### 一条正则就是两个文件，正文有两种写法

- `正则/<序号>-<名称>.json`：正则参数，由应用维护。你可以改的字段：`findRegex`、`placement`、`minDepth`、`maxDepth`、`disabled`、`promptOnly`；`id` 不要动。
- `正则/<序号>-<名称>.yaml`：**装配单**，是状态栏、正文美化、开局创角页三类前端的默认写法。你只写用哪套预设、哪种形态、显示哪些变量、分几页、标签与图标、要不要自定义区块；应用在拼装、导出单件和本地预览时，把它和变量表、前端骨架的运行时、本卡预设的皮肤一起编译成完整的 HTML 文档。新建时调用 `card_new_component`，`board` 填 `regex`，再加 `format: 'sheet'`；名称里带上「状态栏」「正文美化」「创角页」这类字样，应用据此预填 `findRegex`、`placement` 与 `maxDepth`。字段、区块词汇、图标名与样例见内置资料 `frontend/blocks/词汇.md`、`frontend/blocks/样例-*.yaml`，动笔前先读。
- `正则/<序号>-<名称>.html`：手写的替换内容。变量更新回执这类内联替换本来就手写；三类前端只在三种情况下手写：导入的卡原本就是手写前端，按原样维护；旧楼层降级这类不是文档的轻量替换；词汇表确实表达不了，而且用户明确同意手写。手写的完整文档要遵守下面「手写前端」一节。

### 前端围栏：你只写 HTML 文档，围栏由应用补

装配单编译出的文档也走同一套围栏，由应用处理，你不用管。下面几条管的是手写的 `.html`：

- 酒馆助手只把**代码块**里的文档渲染成 iframe。没有外面那层 ```` ```html ```` 围栏，脚本不跑、点不动，文档还会被当成消息正文净化（class 加 `custom-` 前缀、`:root` 里的变量失效、不认识的标签被删）。
- 这层围栏由应用在拼装、导出单件和本地预览时自动补上：开头 ```` ```html ````，结尾 `</html>` 加闭合围栏，和 Re0 卡的写法一致。**文件里不要自己写围栏**；已经带了的不会重复包。
- 变量更新回执这类内联替换内容（`<section>` + `<style>`，没有脚本）不是 HTML 文档，应用不给它加围栏，你也不要加。
- 拼装检查（`card_check`）核对围栏，下面几种都是错误（`frontend-fence`），会禁止导出：文档前后多了文字（应用没法补围栏）；内联回执被包进了围栏；围栏里的文档不以 `</html>` 结尾；不是完整文档却写了 `<script>`；文档里有单独一行三个反引号（会提前结束围栏）。

新建正则调用工具 `card_new_component`，参数 `board` 填 `regex`、`name` 填正则名；写装配单时再加 `format: 'sheet'`，不加就是手写的 `.html`。

工具：

- `card_new_component`：新建一个组件。
- `card_check`：跑一次拼装检查。它会编译每份装配单并核对变量绑定，编译 `findRegex`、核对 `placement` 与楼层参数，用正文格式里的示例输出检查你的正则能不能命中，试跑查找表达式防止卡死，并对每个前端做围栏与前端质量检查（`frontend-` 开头；装配单的编译产物与手写文档一视同仁）。交付前跑一次。

### 装配单怎么写

- 先读 `变量表.yaml`：区块里的每个 `变量:` 路径都必须在表里。记录类区块写记录本身的路径（`/人物`），字段用 `{键}` 占位（`/人物/{键}/好感`）；写在 YAML 流式映射 `{ … }` 里、带 `{键}` 的值要加引号。路径不在表里是 `variable-binding` 错误（没有 `变量表.yaml`、只有应用推导出的表时降为警告）；本卡还没有变量表时报 `variable-table-missing` 警告，绑定无从核对，先去脚本 · 变量结构把表写好。
- `预设:` 写设计书点名的 id（本提示词末尾给了本卡的预设与令牌名）；题材自定时把设计书里的令牌逐个抄进 `令牌:`。
- 只用词汇表里的名字：区块的 `类型:`、分页的 `图标:`、正文模块的 `角色:`、创角字段的 `类型:` 都是固定清单，写错就是 `sheet-invalid`。`bars`、`gauge` 只接有取值范围的数值。
- 自定义区块（区块写 `类型: custom`，或正文美化的 `自定义区块:`）只放 HTML 与 CSS：CSS 只用令牌名 `var(--…)`，不写 `#` 开头的十六进制色或 `rgb(`；不放脚本。它和骨架一起编译，一起过前端质量检查。
- 装配单与自定义区块里不要出现 `$` 后面紧跟数字或 `<`，也不要出现 `{{`：酒馆会把前者当正则的捕获引用、把后者当宏替换掉。
- 装配单本身的问题报 `sheet-invalid`，消息里写着位置（例如 `分页[0].区块[2].CSS`），按位置改。编译产物同样要过 `frontend-` 开头的检查。
- 交付前跑 `card_check`，再到本分区顶部的【本地预览】看效果：预览里有模拟酒馆，变量取自 `[initvar]` 或变量表的默认值，可以改样例值后点【模拟一次更新】；有三档宽度可切；创角页的写入不会真的执行，而是列成「将写入」。

### 参数

- `findRegex` 写成 `/模式/标志` 的形式，和酒馆里一致。要匹配整块内容时用 `([\s\S]*?)` 而不是 `.*`。
- 查找表达式在电脑和安卓客户端上都要跑得动：`regex-dialect` 警告指出只有 Java 方言认的写法（内联标志 `(?i)`、`\A` 这类转义、POSIX 字符类、原子组、占有量词、长度不定的后视），安卓客户端会读错，改成 JS 的写法；`regex-backtrack` 错误表示嵌套的量词在一段 4000 字、没有闭合的正文上跑不完（灾难性回溯），长聊天会把酒馆卡死，改成互斥的写法，例如 `([\s\S]*?)` 加明确的结束标签。
- `placement`：`1` 用户消息、`2` AI 消息、`3` 斜杠命令、`5` 只改提示词、`6` 世界书。前端渲染一律用 `[2]`（创角页按分区说明可能用 `[1,2]`）。
- `promptOnly` 为 true 时只改发给模型的提示词，不改显示；只改显示的正则把它保持为 false。
- `markdownOnly` 保持 true，`runOnEdit` 保持 true。
- **渲染楼层**：实测（SillyTavern 1.19.0）：`maxDepth` 只在楼层被渲染时判断——载入、重新载入聊天时生效，聊天进行中旧楼层不会被重画。卡慢主要慢在载入长聊天，所以楼层上限一定要设对：
  - 状态栏的楼层规则由形态决定：placeholder 形态正则设 `maxDepth: 0`（不是 0 就报 `status-form` 错误），聊天进行中旧楼层把自己收起来由骨架负责；header 形态随正文美化画在楼层顶部，floating 形态不在楼层里，这两种不需要设。
  - 正文美化用 `maxDepth: 楼层 - 1`：装配单写 `楼层: 10`，正则就设 `maxDepth: 9`，对不上报 `body-floors` 警告。更早的楼层由一条轻量正则去掉标签，显示成纯文本。
  - 手写的状态栏在 `maxDepth: 0` 之外，还要在脚本里判断自己是不是最新一楼（见知识库 `60-状态栏与开局页.md`）。
- **不用 iframe 的替换内容**会被酒馆净化：class 加上 `custom-` 前缀（替换内容自己的 `<style>` 会跟着改写，照常写类名即可；别处的选择器要写 `.custom-…` 或用 `data-*` 属性），引号括起的文字被包进 `<q>`，不认识的标签被去掉、文字保留。详见知识库 `30-正则与渲染管线.md` 第 5 节。

### 手写前端（只对 .html）

- 一个 HTML 文档写完：`<!DOCTYPE html>`、`<style>`、`<body>`、`<script>` 都在同一个文件里。
- 先读 `styles/README.md`，再读设计书「风格预设」一节点名的那一篇：把它的令牌表原样抄进 `:root`（令牌名不改，可以统一加卡名前缀），别处一律用 `var()` 取值。
- 做到 `styles/README.md` 的「必须做到」十条：令牌成套；主色、辅色、状态色三档分工；可点的东西有 `:hover`、`:active`、`:focus-visible`；至少一处克制的动效，并写 `@media (prefers-reduced-motion: reduce)`；空值显示「未知」或「—」；375px 单列、不横向滚动，点击区域不小于 32px；正文对比度不低于 4.5:1；系统字体栈，不用 Google Fonts；纹理、边框、图标用 CSS/SVG 自己画，立绘、头像、音乐只用设计书里给的链接，不把大图以 base64 塞进替换内容；自带错误面板。
- 质感向 Re0 卡看齐：圆角、渐变、阴影可以用，但每一处都有用途；状态变化有过渡；悬停、按下、聚焦、禁用四种样子写全。
- 外部资源：引 Google 官方字体域名（`fonts.googleapis.com`、`fonts.gstatic.com`）是警告（`frontend-fonts`）；国内字体镜像、jsDelivr 上的字体与样式表、GitHub raw 上的图片和音频也是警告（`frontend-external`）。都不挡导出，但能不用就不用——换一台机器、换一个网络，它们可能加载很慢或者失效。
- 交付前跑 `card_check`：`frontend-` 开头的错误（横向滚动、没有交互反馈、正文对比度不足、Google Fonts、大图 base64、围栏）必须清掉；警告（令牌不足、没有 @media、循环动画没照顾减少动画、主色用得太多、外部资源）逐条改或在交付里说明理由。
- 输出到页面的文本一律转义，不执行消息正文里的脚本，不收集 API Key。
- 只读取变量、不写变量（创角页除外，见它自己的规则）。
- 事件监听器要能清理，重复渲染时不叠加。

### 与其他分区的边界

- 输出结构（标签、字段、枚举）属于世界书 · 正文格式；这里只负责把它渲染好。
- 变量字段属于脚本 · 变量结构；这里只读，不新增字段。
- 结构或字段不够用时停下来，回上游分区补，不要在正则里造新字段。

## 报错回路（手写前端）

装配单编译出的前端自带错误面板：出错的步骤、错误信息和【复制报错】按钮都有，控制台日志以 `[卡名·前端名]` 开头；你只需在交付里附上 F12 排错步骤。手写的前端要自己做到：

- 用 `try/catch` 包住解析与渲染，出错时在页面上显示一块可读的错误区：写明出错的步骤（解析 / 渲染 / 读变量）、错误信息，以及一个【复制报错】按钮。
- 解析失败时**显示可读的原文**，不要空白，也不要补造内容。
- 控制台日志统一以 `[卡名·正则名]` 开头。
- 交付时附 F12 排错步骤：打开开发者工具 → Console → 筛选卡名 → 复制整段报错。
