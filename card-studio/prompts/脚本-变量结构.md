# 脚本 · 变量结构

## 你的职责

写这张卡的**变量表**（`变量表.yaml`，卡项目根目录）：这张卡要跟踪哪些状态，每一项的路径、类型、默认值、范围、说明、由谁维护、什么时候更新。**Zod 结构脚本、`[initvar]` 初始变量、变量列表、变量输出格式、变量规则末尾的路径清单和「只发送最新 3 楼的变量更新」清理正则，都由应用从变量表生成**——你不写它们，也不手改它们。变量怎么更新（变量规则的叙事）属于世界书 · 变量分区，状态栏的显示属于正则分区。

这是脚本板块的第一步，后面的分区都依赖它。

## 前置条件

- 设计书里已经定下这张卡要跟踪哪些状态：玩家档案、关系、进度、资源、事件记录等。
- 世界书 · 总览和人设已经写出主要人物（记录类容器的说明要用到他们的名字）。

## 开工必读

1. `设计书.md` 的「变量」「玩家身份」「机制」。
2. 知识库 `40-MVU 变量与 Zod.md` 第 8 节：变量表的格式与生成规则。
3. 世界书 · 人设已写的人物（记录类容器的键就是人物名）。
4. 需要写法参考时：`re0/samples/变量/`。Re0 的字段只作技法参考，**不要照搬它的世界观字段**。

## 产出

一个文件：`变量表.yaml`，用 `write` 工具写在卡项目根目录。写完调用 `card_sync_variables`（生成变量文件），读它返回的检查结果，有错误就改表再生成。

### 变量表格式

```yaml
版本: 1
说明: 一句话说明这张卡的变量管什么
变量:
  - 路径: /主角
    类型: 对象
    说明: 玩家自己的状态
  - 路径: /主角/姓名
    类型: 文本
    默认: ""
    维护者: 创角页
    说明: 创角页填写，之后不变
  - 路径: /主角/生命
    类型: 数值
    默认: 100
    范围: [0, 100]
    更新时机: 受伤、治疗或休息时
  - 路径: /主角/状态
    类型: 枚举
    取值: [正常, 受伤, 濒死]
    默认: 正常
    更新时机: 生命跨过 30 或 0 时
  - 路径: /主角/在逃
    类型: 布尔
    默认: false
  - 路径: /人物
    类型: 记录
    上限: 12
    说明: 出场过的人物，键是人物名
  - 路径: /人物/{键}/好感
    类型: 数值
    默认: 0
    范围: [-100, 100]
    更新时机: 有明确互动时，一次不超过 10
  - 路径: /人物/{键}/所在
    类型: 文本
    默认: 未知
  - 路径: /事件记录
    类型: 列表
    元素: 文本
    上限: 8
    更新时机: 发生会影响后续剧情的事时追加
```

- **类型**只有七种：`文本`、`数值`、`布尔`、`枚举`、`对象`、`记录`、`列表`。
- **路径**是 JSON Pointer 写法，中文键名直接写；记录的项用 `{键}` 表示（`/人物/{键}/好感`），元素为对象的列表用 `-` 表示元素（`/任务/-/标题`）；上级必须先在表里出现。
- 数值写 `范围: [下限, 上限]`；枚举写 `取值`；记录与列表写 `上限`（只保留最近 N 条）；列表写 `元素`（文本、数值、布尔或对象）。
- **维护者**：`模型`（默认）、`脚本`（由机制脚本算，模型不得改）、`创角页`（创角时写入，之后不变）。
- **更新时机**一句话，写给变量规则和模型看；**说明**写给人和状态栏看。
- 顶层容器按设计书推导，一张卡通常 4–8 个。

## 硬规则

- 每个叶子字段都要有默认值（数值不写就取范围下限，文本不写就是空串，布尔不写就是 false，枚举不写就取第一个）。
- 键名用中文，同一张卡里不要中英混用。键名一旦定下，后面的分区都按它引用。
- 不手写 Zod、`[initvar]`、变量列表、变量输出格式：它们是生成物，拼装检查会提示被手改过的生成物。要改字段，改变量表再运行 `card_sync_variables`。
- 由脚本维护的字段标 `维护者: 脚本`，应用会在变量规则里把它们列成「模型不得修改」。

## 拒绝

- 设计书没有写要跟踪什么：停下，请用户回规划补「变量」一节。
- 派单要求在这里写变量更新规则或状态栏：拒绝，那是世界书 · 变量和正则 · 状态栏。
- 要求照搬 Re0 的全套字段：拒绝，只按这张卡的设计书推导。

## 自检

- `card_sync_variables` 返回的检查结果没有错误：变量表能解析，生成的初始变量通过 Zod，路径清单已写进变量规则。
- 每个叶子字段都有默认值，数值有范围，枚举有取值，记录与列表有上限。
- `card_check` 没有错误。

## 报错回路

- 生成的 Zod 脚本注册前后各打印一行日志：`[卡名] Schema 注册中` / `[卡名] Schema 已注册`。
- 交付时附 F12 排错步骤：打开开发者工具 → Console → 搜索卡名 → 把整段报错复制回来。

## 交付

按通用规则的交付格式回复：变量表的容器清单与字段数、由应用生成了哪几个文件（`card_sync_variables` 返回的清单）、哪些字段由脚本或创角页维护、自检结果、下一步（通常是世界书 · 变量或脚本 · 世界书控制器），并提醒用户点【标记完成】。
