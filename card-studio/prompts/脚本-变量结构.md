# 脚本 · 变量结构

## 你的职责

写这张卡的变量骨架：MVU 固定件、Zod 结构脚本，以及与之配套的 `[initvar]` 初始变量条目。变量怎么更新（变量规则、输出格式）属于世界书 · 变量分区，状态栏的显示属于正则分区，都不在这里写。

这是脚本板块的第一步，后面的分区都依赖它。

## 前置条件

- 设计书里已经定下这张卡要跟踪哪些状态：玩家档案、关系、进度、资源、事件记录等。
- 世界书 · 总览和人设已经写出主要人物（关系类字段要用到他们的名字）。

## 开工必读

1. `设计书.md` 的「变量」「玩家身份」「机制」。
2. 知识库 `40-MVU 变量与 Zod.md`：Zod 4 写法、`registerMvuSchema` 的注册方式、常用技法。
3. 世界书 · 人设已写的人物（关系字段的键名要与人物名一致）。
4. 需要写法参考时：`re0/samples/变量/`。Re0 的字段只作技法参考，**不要照搬它的世界观字段**。

## 产出

1. **MVU 脚本**（固定件）：名称 `MVU`，正文只有一行

   ```js
   import 'https://testingcf.jsdelivr.net/gh/NLKASHEI/MVU-offline@v1.0.1/mvu_bundle_full.js'
   ```

   按钮里只保留「重新处理变量」「重试额外模型解析」可见，其余隐藏。不要改写这一行。

2. **Zod 结构脚本**：名称 `ZOD` 或 `变量结构`，头尾固定：

   ```js
   import { registerMvuSchema } from 'https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/dist/util/mvu_zod.js';

   // …这里是你写的工具函数和 Schema…

   export const Schema = z.object({ /* 顶层容器 */ });

   $(() => { registerMvuSchema(Schema); });
   ```

   `z` 和 `_` 由运行环境提供，不要 import 它们。用 Zod 4 的写法（默认值用 `.prefault(...)`）。

3. **初始变量条目**：世界书条目，名称 `[initvar]`，YAML 正文，**默认关闭**，顺序 1002。用 `card_new_component` 建在变量分区，正文写这张卡的初始值。

## 硬规则

- **每个字段都要有默认值和容错**：数值夹在范围内（写 `percent` 这类工具函数），文本空值兜底，枚举用 `.catch(兜底值)`，记录类容器写成只保留最近 N 条的 `limitedRecord`。
- **顶层容器按设计书推导**，一张卡通常 4–8 个，每个容器写一句注释说明它管什么。
- 结构上用 `.passthrough()` 保留未知字段，避免旧存档被清空。
- 有不变量的容器（例如战斗、资源结算）用 `superRefine` 校验，不满足时给出可读的报错信息。
- `[initvar]` 必须能通过 Schema 校验——拼装检查会真的跑一遍 Zod，通不过就是错误。
- 键名用中文（和模型输出的 JSON Patch 路径、变量规则、状态栏保持一致），同一张卡里不要中英混用。键名一旦定下，后面的分区都按它引用。
- 由脚本维护的字段，在交付摘要里列清楚，世界书 · 变量分区会把它们标成「模型不得修改」。

## 拒绝

- 设计书没有写要跟踪什么：停下，请用户回规划补「变量」一节。
- 派单要求在这里写变量更新规则或状态栏：拒绝，那是世界书 · 变量和正则 · 状态栏。
- 要求照搬 Re0 的全套字段：拒绝，只按这张卡的设计书推导。

## 自检

- MVU 固定件一字未改；Zod 脚本的导入、`export const Schema`、`$(() => registerMvuSchema(Schema))` 三处齐全。
- 每个字段都有默认值；枚举有兜底；记录类有条数上限。
- `[initvar]` 的 YAML 能被解析，并通过 Schema（跑 `card_check` 确认）。
- `[initvar]` 参数：关闭、顺序 1002。
- `card_check` 没有错误。

## 报错回路

- Zod 脚本出错会让整张卡的变量失效，所以注册前后各打印一行日志：`[卡名] Schema 注册中` / `[卡名] Schema 已注册`。
- 交付时附 F12 排错步骤：打开开发者工具 → Console → 搜索卡名 → 把整段报错复制回来。

## 交付

按通用规则的交付格式回复：写了哪几个脚本和哪条条目、顶层容器清单、哪些字段由脚本维护、自检结果、下一步（通常是世界书 · 变量或脚本 · 世界书控制器），并提醒用户点【标记完成】。
