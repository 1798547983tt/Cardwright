# 正则 · 变量更新渲染

## 你的职责

把模型输出的 `<UpdateVariable>` 块渲染成一张默认折叠的回执，让玩家能看懂这一回合改了什么。共两条正则：更新中、更新完成。只改显示，不改提示词。

## 前置条件

- 变量表已经写好并生成：变量输出格式条目已由应用生成，`<UpdateVariable>` 里有哪些子块（通常是 `<Analysis>` 与 `<JSONPatch>`）以它为准。
- 变量表已经写好并生成，字段名确定。

## 开工必读

1. `设计书.md` 的「变量」一节。
2. 应用生成的「变量输出格式」条目（`世界书/变量/9996-变量输出格式.md`）：子块名称、JSON Patch 的写法。
3. 知识库 `30-正则与渲染管线.md`。
4. 需要做法参考时：`re0/samples/正则/变量更新.md`。

## 产出

两条正则，`placement: [2]`，`markdownOnly: true`，`promptOnly: false`：

1. **变量更新中**：匹配还没闭合的块，例如 `/<UpdateVariable>(?![\s\S]*<\/UpdateVariable>)[\s\S]*$/g`。替换成一行「变量更新中…」的回执头，不放捕获内容。
2. **变量更新完成**：匹配完整的块，用捕获组分别取出 Analysis 与 JSON Patch，放进默认折叠的回执：折叠时一行摘要，展开后显示「本轮依据」（Analysis）与「补丁」（JSON Patch）。

**优先写成不带脚本的回执**：`<details>` + `<summary>` + 两个 `<pre>`，样式写在 `<style>` 里。这样它走酒馆自己的净化流程，不需要 iframe，也最不容易出错。只有设计书明确要求逐条列出补丁时，才写脚本解析 JSON Patch。

## 硬规则

- **只改显示**：不要改写发给模型的内容。固定件「只发送最新 3 楼的变量更新」由应用在生成变量文件时加入，**不在本分区写**。
- **捕获组要防注入**：捕获 Analysis 与 Patch 的组不允许跨过 `<` 和代码围栏，例如 `((?:(?!<|\x60{3}|~{3})[\s\S])*?)`。这样模型在里面写了标签时整条不匹配、原样显示，而不是把标签塞进你的 HTML。
- 捕获内容只放进 `<pre>`，不要放进属性值或 `<style>`。
- 不带脚本的回执直接插进消息，会被酒馆净化（实测 1.19.0）：class 加上 `custom-` 前缀，回执自己的 `<style>` 会跟着改写，照常写类名；`<pre>` 里 JSON 的双引号会被包进 `<q>`，显示成对白颜色——在回执的 `<style>` 里写 `q { color: inherit; }`。
- 默认折叠。展开状态不要写进 MVU 变量。
- **JSON Patch 不带旧值**：逐条列出时只写「操作 · 路径 · 新值」，不要去猜旧值，也不要读 MVU 当前值来补。
- 需要脚本时，JSON 解析失败就显示原文并在错误面板里说明，不要吞掉内容。
- 一次渲染只处理自己匹配到的这一块，不扫描其他楼层。

## 拒绝

- 变量输出格式还没生成：停下，先去脚本 · 变量结构写变量表并生成。
- 派单要求在这里改提示词或裁剪历史楼层：拒绝，那是固定件和拼装的事。

## 自检

- 两条正则都能编译，`findRegex` 与实际输出对得上（用变量输出格式里的示例试一次）。
- 未闭合的块只被「更新中」匹配，闭合的块只被「更新完成」匹配，两者不重叠。
- Analysis 里故意写一个 `<b>`：完成回执不匹配、原文照常显示。
- 折叠与展开在 375px 宽度下可用，长补丁在 `<pre>` 里横向滚动而不是撑破页面。
- `card_check` 没有错误。

## 报错回路

- 不带脚本的回执：出错的表现是「整条没匹配、显示原文」，交付时写明怎么判断是正则没命中（F12 → Elements 里找不到回执的根节点）。
- 带脚本的回执：解析与渲染分别 `try/catch`，错误进错误面板，带【复制报错】按钮；控制台日志以 `[卡名·变量更新]` 开头。
- 交付时附 F12 排错步骤。

## 交付

按通用规则的交付格式回复：写了哪两条正则、各自的 `findRegex` 与参数、是否用了脚本、自检结果、下一步，并提醒用户点【标记完成】。

提醒用户在本分区顶部的【本地预览】里看两种状态：生成完成、生成中（还没有 `</UpdateVariable>`）。预览的样本取自示例输出里的 `<UpdateVariable>`，没有就取世界书 · 变量里第一段完整的 `<UpdateVariable>`。如果那一段是带 `${…}` 占位的输出模板，完成回执会显示「没有命中」——这不是正则的错，在示例输出里补一段填好真实内容的 `<UpdateVariable>` 即可，不要往生成的变量输出格式条目里加。
