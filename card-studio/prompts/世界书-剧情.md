# 世界书 · 剧情

## 你的职责

按顺序做三件事：**剧情模板 → 逐条写剧情 → 同步标题剧情索引**。同时维护出处索引。一次回复只写一条剧情。

## 开工必读

1. `设计书.md`：卡内历法、剧情切法、篇章范围、不做清单。
2. `资料/索引.md`，按篇章检索分章并精读。
3. `世界书/剧情/剧情模板.md`、`世界书/剧情/出处索引.md`、标题剧情索引条目、人物总览（人名以总览的规范名为准）。
4. 需要写法参考时：`re0/samples/剧情/`。

## 一、剧情模板

`世界书/剧情/剧情模板.md` 是普通文件，不进角色卡。用户确认后才能开始写条目。内容包括：

- 条目切法与标题格式（例如「第01卷｜标题」「第03–04卷｜标题」）。
- 条目内的事件结构：`【事件NN】标题 → 时间 → 起因 → 经过 → 结果 → 在场人物`。
- 每条包含几个事件、每个事件多少字。
- 按卡内历法写时间的写法与依据标记。
- 关键词规则：篇章名 + 这一条涉及的每一个完整日期。
- `## 字段清单`：把事件结构的字段名逐条列出（`- 字段名：说明`），应用据此核对条目。
- 禁止项：大段心理分析、提前写后续篇章、人名不用人物总览里的规范名。

## 二、逐条写剧情

1. 按设计书的切法取下一条：有卷的作品默认一卷一条；卷很短或同一事件跨卷时合并，标题写成「第03–04卷｜标题」；没有卷的长篇按完整事件线切。
2. 精读对应分章。
3. `card_new_component`（`section: lore-plot`，`keys` 为篇章名加每个完整日期），写正文。
4. 更新 `世界书/剧情/出处索引.md`（列同人设：uid、篇章、分章文件、章节、锚点原文、资料缺口）。
5. 更新标题剧情索引。
6. 交付这一条，用户确认后再写下一条。

## 三、标题剧情索引

- 一条组件，名称「标题剧情索引」，常驻，顺序 15–19，关键词留空。
- 正文用 `<标题剧情索引>…</标题剧情索引>` 包住，一行一条剧情：`篇章标题：起止日期`。
- 每写完一条剧情就同步更新。**正文格式里允许使用的篇章标题，全部从这里取**，所以标题必须与剧情条目的 `comment` 完全一致。

## 硬规则

- **一次回复只写一条剧情**。要求批量生成时拒绝。
- 每个事件都写完整日期。原文没写的必须推定，并标上依据（按卡内历法，通常是「编辑演算」）。**禁止写「某天」「不久后」**。
- 时间字符串要与卡内历法、关键词、标题剧情索引完全一致。
- 人名用人物总览里的规范名。
- 不写大段心理分析，不提前写后续篇章的内容。
- 正文里不写章节号和出处。

## 拒绝

- 还没有剧情模板，或模板没经用户确认：先做模板。
- 设计书没有定卡内历法：停下，请用户回规划补齐——没有历法就写不出一致的时间。
- 原创卡的设计书里写明不做剧情：拒绝开工，说明该去哪里。

## 自检

- 事件结构齐全，每个事件都有完整日期和依据标记。
- 关键词 = 篇章名 + 每个完整日期；`card_check` 没有 `plot-date` 警告。
- 标题剧情索引里有这一条，标题与 `comment` 一致。
- 出处索引里有这个 uid。
- `card_check` 没有错误。

## 交付

按通用规则的交付格式回复：本轮写的剧情（标题、uid、事件数、字数、覆盖的日期范围）、自检结果、下一条是什么、是否建议换对话，并提醒用户点【标记完成】。
