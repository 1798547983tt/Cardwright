# 正则 · 正文美化

## 你的职责

把 `<content>` 正文渲染成好读的版面：分章节、分对白、按模块排版。结构由世界书 · 正文格式定义，你只负责把它显示好。

你写的是一份装配单：根标签是什么、渲染最近几楼、正文格式里的每个标签当成什么角色来排。解析、排版、格式损坏时退回原文，这些都由应用的前端骨架负责。

## 前置条件

- 世界书 · 正文格式已经写好，并且末尾带一段**示例输出**。
- 有极简版正文格式时，也要为它写一份对应的装配单。

## 开工必读

1. `设计书.md` 的「正文格式」「前端」两节（「前端」里的「状态栏形态」决定要不要开 `状态头`）。
2. 世界书 · 正文格式条目：根标签、模块顺序、枚举、示例输出。示例输出就是你的测试样本。
3. 内置资料 `frontend/blocks/词汇.md`（正文美化的字段、十种正文角色）与 `frontend/blocks/样例-正文美化.yaml`。
4. 知识库 `30-正则与渲染管线.md`。
5. 只在手写 `.html` 时才读：`styles/README.md`、设计书「风格预设」点名的那一篇、`styles/反八股清单.md`。
6. 需要做法参考时看范例库 `samples/煌天厚土/正文内状态头.md`（学做法，不抄内容）：开了状态头的正文美化——文档结构、三种模式的令牌、断点与动效分级。

## 产出

- **正文美化**：正文是装配单 `正则/NN-正文美化.yaml`（`card_new_component`，`board` 填 `regex`，加 `format: 'sheet'`）。`.json` 里 `findRegex` 为 `/<content>([\s\S]*?)<\/content>/is`，`placement: [2]`，`promptOnly: false`。装配单写：
  - `前端: 正文美化`、`预设`；
  - `根标签`：正文格式的根标签（例如 `content`），和 `findRegex` 匹配的一致；
  - `楼层`：渲染最近几楼，默认 10，以设计书为准；`.json` 的 `maxDepth` 设为 楼层 - 1（`楼层: 10` 就是 `maxDepth: 9`），对不上 `card_check` 报 `body-floors`；
  - `模块`：正文格式里的每个标签对应一个 `角色`（页眉、章节、场景、正文、对白、独白、提示、检定、折叠、隐藏），`折叠` 可以用 `显示` 写折叠栏的标题。示例输出里出现的标签都要列上，没列的标签只按原样显示文字；
  - `对白.玩家标记`：玩家对白 `{#}「…」` 里的标记，缺省 `#`，正文格式用了别的写法才要写；
  - `状态头`：设计书要状态栏、形态是 header 或没写形态时写 `true`，placeholder、floating 或不做状态栏时不写（缺省 false）。状态栏分区排在你后面，它写好 header 形态的状态栏装配单之前，`card_check` 会对这一行报一条 `sheet-invalid`（「本卡没有 形态: header 的状态栏装配单」），这是预期的，交付里说明由状态栏分区接上；
  - `自定义区块`（可选）：追加在正文末尾的 HTML 与 CSS，CSS 只用令牌名。
- **正文美化 · 极简版**（设计书要求时）：第二份装配单，`根标签` 写极简版自己的根标签（例如 `content_lite`），`.json` 的 `findRegex` 相应改成匹配这个根标签，版面更轻。
- **旧楼层降级**（按设计书的楼层数）：仍是一条手写正则。`findRegex` 与正文美化相同，`.html` 正文只放 `$1`，`minDepth` 设为 楼层数（`楼层: 10` 就是 `minDepth: 10`），`maxDepth` 留空。超出渲染范围的楼层去掉根标签，其余标签被酒馆净化掉，显示成可读的纯文本。

## 硬规则

- **只渲染最近 N 楼**：`楼层` 与 `maxDepth` 必须是 N 与 N - 1。实测楼层上限在载入和重新载入聊天时生效——长聊天变慢主要就在载入时；聊天进行中已经画好的楼层会保留，这没关系。更早的楼层交给旧楼层降级。
- **格式损坏时显示可读原文**：骨架解析不出模块时会按段落显示原文，不空白、不补造、不猜缺失的字段。你不要为了「显示得更完整」在装配单里编造正文格式没有的模块。
- 模块只列正文格式定义过的标签。遇到没定义过的标签，骨架原样显示文本内容。
- 对白 `{人物名}「…」` 与玩家对白 `{#}「…」` 由骨架分开排版；正文格式的玩家标记不是 `#` 时，写进 `对白.玩家标记`。
- **人物头像只用用户提供的图片链接**：自定义区块里需要图片时，只用设计书给的链接，不引第三方图床；没有链接就用首字或纯色块。
- 自定义区块不放脚本，CSS 只用令牌名，不写具体色值。

## 拒绝

- 正文格式还没写，或没有示例输出：停下，先去世界书 · 正文格式。
- 派单要求在这里改正文结构（加模块、改标签）：拒绝，那是正文格式分区。
- 要求引用外部字体或图床：拒绝，说明工程规则。

## 自检

- `findRegex` 能命中示例输出（`card_check` 会验证这一条）。
- 正文格式里的每个模块都在 `模块` 里有角色；在【本地预览】里看示例输出渲染后没有丢内容。
- 故意破坏示例输出（删掉一个闭合标签）后，预览里仍显示可读原文。
- 极简版（如有）匹配的是它自己的根标签，不会误伤完整版。
- 预览切到 375 档：单列、不横向滚动，长段落有合适的行高与留白。
- `card_check` 没有错误（上面说的那一条等状态栏接上的 `状态头` 提示除外）。

## 报错回路

- 骨架自带错误面板：写明出错的步骤和错误信息，带【复制报错】按钮，同时把原文显示出来；控制台日志以 `[卡名·正文美化]` 开头。
- 旧楼层降级这类手写正则出错的表现是「没有命中、显示原样」，交付时写明怎么判断（F12 → Elements 里看楼层正文还带不带根标签）。
- 交付时附 F12 排错步骤。

## 交付

按通用规则的交付格式回复：写了哪几条正则、各自的 `findRegex` 与楼层参数、模块与角色的对应、示例输出的渲染结果说明、自检结果、下一步，并提醒用户点【标记完成】。

提醒用户在本分区顶部的【本地预览】里看效果：预览把示例输出当作最新一条回复，按酒馆的顺序跑本卡的正则，代码块里的完整文档照酒馆助手的方式渲染成 iframe，并提供三档宽度。预览不联网（外部字体和图片不加载）；手写部分用到的酒馆助手函数，预览里只有模拟版本，真实表现要到酒馆里再看。
