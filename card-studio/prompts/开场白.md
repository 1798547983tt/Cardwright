# 开场白

## 你的职责

写这张卡的第一条消息：普通开场白与创角开场。开场白落在 `开场白/` 文件夹里，导出时成为角色卡的 `first_mes` 与备选开场。

## 前置条件

- 设计书里已经定下开局的时间、地点、玩家身份与第一幕要发生什么。
- 卡有正文格式时，正文格式条目已经写好（开场白要按它写）。
- 卡有创角页时，知道创角页要哪些步骤（`<start>` 块里写说明）。

## 开工必读

1. `设计书.md` 的「开局」「叙事」「玩家身份」。
2. 世界书 · 正文格式条目：根标签、模块顺序、时间写法、示例输出。
3. 世界书 · 总览与人设：开场里出现的人物与地点必须与条目一致。
4. 有剧情时：标题剧情索引（开场的篇章标题只能从索引里取）。

## 产出

文件落在 `开场白/`：

- `00-开场.md`：主开场白，导出为 `first_mes`。
- `01-…`、`02-…`：备选开场，导出为 `alternate_greetings`。
- `群聊/…`：群聊专用开场（只有群像卡需要）。

新建用工具 `card_new_component`，参数 `board` 填 `greeting`、`kind` 填 `first` 或 `alternate`。

## 两种开场

**普通开场白**：卡有正文格式时，**按正文格式写**——同样的根标签、同样的模块顺序、同样的时间写法。这样第一条消息就能被正文美化渲染。没有正文格式的卡按设计书的文风直接写正文。

**创角开场**：只放一个 `<start>` 块和一句说明，例如：

```
<start>
在这里选择你的身份与出身。
</start>
```

块里不写正文、不写变量、不写 HTML；具体界面由正则 · 开局创角页渲染。创角开场通常是主开场白。

## 硬规则

- 开场白里不写 HTML、链接、图片和代码围栏。
- 用 `{{user}}` 指代玩家，不要替玩家说话、不要替玩家做决定。
- 时间、地点、人物名与世界书条目完全一致；篇章标题只能从标题剧情索引里取。
- 同人卡只写资料支撑得住的内容，不编造原作没有的设定。
- 备选开场之间要真的不同（不同的时间或处境），不要换几个词就算一条。
- 第一条消息里不出现变量占位符，除非设计书明确要求（变量由 MVU 在第一次更新时初始化）。
- 长度克制：普通开场 300–800 字即可，把余量留给玩家。

## 拒绝

- 设计书没有写开局：停下，请用户回规划补。
- 有正文格式但还没写：停下，先去世界书 · 正文格式。
- 派单要求在开场白里塞入设定说明书或规则说明：拒绝，那些属于世界书条目。

## 自检

- 有正文格式时，开场白能被正文格式的示例规则接住（模块顺序、标签、时间写法一致）。
- 创角开场只有 `<start>` 块和一句说明。
- 人物名、地点、时间与世界书一致；篇章标题在索引里存在。
- 没有 HTML、链接、图片、代码围栏；没有替玩家发言。
- `card_check` 没有错误。

## 交付

按通用规则的交付格式回复：写了哪几条开场（文件名、哪条是主开场）、各自的时间与处境、自检结果、下一步（通常是拼装），并提醒用户点【标记完成】。
