# 正则 · 开局创角页

## 你的职责

把开场白里的 `<start>…</start>` 换成一个分步的创角页：玩家选完身份与设定后，把结果写进聊天世界书，并把开场信息填进酒馆输入框。这是整张卡里唯一会写数据的正则。

## 前置条件

- 设计书写明了创角步骤与字段；同人卡写明可选的原作人物。
- 脚本 · 变量结构已经写好：创角页要写入的初始值都在 Schema 里。
- 开场白分区已经写好带 `<start>` 块的创角开场（或与它并行进行，交付时对齐）。

## 开工必读

1. `设计书.md` 的「玩家身份」「创角页」两节。
2. 脚本 · 变量结构的 Schema 与 `[initvar]`。
3. 知识库 `60-状态栏与开局页.md`、`50-酒馆助手前端基础.md`（聊天世界书接口、`generateRaw`、输入框写入）。
4. ADR 0012（玩家设定写入聊天世界书，不支持时退回主世界书）。
5. 风格预设 `styles/` 与反八股清单。
6. 需要做法参考时：`re0/samples/正则/`（Re0 的「魔女茶会创角向导」）。

## 产出

一条正则，名称 `开局创角页`：

- `findRegex`：`/<start>([\s\S]*?)<\/start>/gsi`，`placement`：`[1,2]`（开场白可能出现在两侧），`promptOnly`：false。
- 替换内容是一个完整 HTML 文档：分步向导（身份 → 设定 → 关系 → 启程之类，步数以设计书为准），最后一页是核对清单。

## 完成后的动作（按顺序）

1. **写入玩家设定**：写进**当前聊天的聊天世界书**。
   - 条目：常驻、角色定义前、顺序 100，名称按设计书（例如「[卡名] 初始人物设定」）。
   - 世界书名为「卡名 · 存档名」；写入前检查重名，已存在就更新，不要新建第二本。
   - 酒馆版本不支持聊天世界书时，**退回写入角色主世界书**，并在创角页上明确提示玩家这一点。
2. **填入开场信息**：把开场信息填进酒馆输入框并发送。
   - 输入框里已经有内容时**不要覆盖**：改为复制到剪贴板，并提示玩家自己粘贴。
3. **写入初始变量**（设计书要求时）：只写 Schema 里有的字段，值必须在取值范围内。

## 硬规则

- **不收集 API Key**。「AI 帮写」只走酒馆当前的模型连接（`generateRaw`），不提供任何填 Key 的输入框，也不请求外部接口。
- 每一步都能回退，已填的内容不丢。
- 玩家输入的文本在写入世界书与显示时都要转义。
- 同人卡：可选的原作人物只列资料支撑得住的；玩家也可以建原创角色。
- 写世界书与填输入框都要有明确的成功 / 失败提示，失败时把内容留给玩家复制。
- 手机宽度下可用；步骤条不横向滚动。
- 不在这里定义变量字段，不改世界书里的其他条目。

## 拒绝

- 设计书没有写创角步骤或字段：停下，请用户回规划补。
- 变量结构还没写而创角页要写初始变量：停下，先去脚本 · 变量结构。
- 要求在卡里填 API Key 或接外部模型接口：拒绝，说明规则。

## 自检

- `findRegex` 能命中开场白里的 `<start>` 块。
- 五类动作各验证一次：写聊天世界书成功、聊天世界书不支持时退回主世界书、输入框为空时发送、输入框有内容时复制、写变量后仍通过 Schema。
- 重名检查生效：重复创角不会新建第二本世界书。
- 页面里没有任何 Key 输入框。
- `card_check` 没有错误。

## 报错回路

- 写世界书、填输入框、AI 帮写三处分别 `try/catch`，错误进错误面板，带【复制报错】按钮，并把玩家已填的内容保留在页面上。
- 控制台日志以 `[卡名·创角页]` 开头。
- 交付时附 F12 排错步骤，以及「写入失败时怎么手动补」的说明。

## 交付

按通用规则的交付格式回复：写了哪条正则、创角步骤、写入了哪本世界书与哪些字段、自检结果、下一步，并提醒用户点【标记完成】。
