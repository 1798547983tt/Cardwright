# 正则 · 开局创角页

## 你的职责

把开场白里的 `<start>…</start>` 换成一个分步的创角页：玩家选完身份与设定后，把结果写进聊天世界书，并把开场信息填进酒馆输入框。这是整张卡里唯一会写数据的正则。

你写的是一份装配单：分几步、每步有哪些字段、提交时往哪里写什么。分步向导、核对清单、提交事务、错误面板，都由应用的前端骨架负责。

## 前置条件

- 设计书写明了创角步骤与字段；同人卡写明可选的原作人物。
- 变量表已经写好并生成：创角页要写入的初始值都在表里、值在范围内。
- 开场白分区已经写好带 `<start>` 块的创角开场（或与它并行进行，交付时对齐）。

## 开工必读

1. `设计书.md` 的「玩家身份」「前端」两节，以及其中创角页的步骤与字段。
2. `变量表.yaml`：创角页写入的每个路径都必须在表里，一般是维护者为「创角页」的行；Schema 与 `[initvar]` 由它生成。
3. 内置资料 `frontend/blocks/词汇.md`（创角页的字段、六种字段类型、`写入` 的写法）与 `frontend/blocks/样例-创角页.yaml`。
4. 知识库 `60-状态栏与开局页.md` 的「二、开局页与创角页」。
5. ADR 0012（玩家设定写入聊天世界书，不支持时退回主世界书）。
6. 只在手写 `.html` 时才读：`styles/README.md`、设计书「风格预设」点名的那一篇、`styles/反八股清单.md`，以及知识库 `50-酒馆助手前端基础.md`（聊天世界书接口、`generateRaw`、输入框写入）。

## 产出

一条正则，名称 `开局创角页`，正文是装配单 `正则/NN-开局创角页.yaml`（`card_new_component`，`board` 填 `regex`，加 `format: 'sheet'`）：

- `findRegex`：`/<start>([\s\S]*?)<\/start>/gsi`，`placement`：`[1,2]`（开场白可能出现在两侧），`promptOnly`：false。
- 装配单以 `前端: 创角页` 开头，写 `预设`、`标题`。
- `步骤`：按设计书的步骤与字段写（身份 → 设定 → 关系 → 启程之类，最多 8 步）。字段类型从词汇表的六种里选；同人卡可选的原作人物用 `人物列表`，`选项` 只列资料支撑得住的人物。最后一步的核对清单由应用自动加上，不用写。
- **自定义开局**（建议加）：核对清单之前的最后一步写 `自定义开局: true`，放一个 `长文本` 字段（例如 `补充`），并在 `写入.世界书条目.模板` 与 `写入.开场信息` 的末尾写上它的占位 `{补充}`。玩家想临时加的设定就能随创角写进去，不用改卡。
- `写入.世界书条目`：`名称` 按设计书（例如「[卡名] 初始人物设定」），`模板` 里用 `{键}` 引用字段的值。
- `写入.开场信息`：提交后填进输入框的那段话，同样用 `{键}`。
- `写入.初始变量: true`（设计书要求写初始变量时）：每个要写进变量的字段带 `写入:` 路径，路径是变量表里的行，一般是维护者为「创角页」的那些；滑杆的 `范围` 不超出表里的取值范围。

## 完成后的动作（骨架按这个顺序执行）

玩家在核对清单上提交后，骨架按固定顺序做三件事，你不用写接口调用，只要把装配单的 `写入` 写对：

1. **写入玩家设定**：写进**当前聊天的聊天世界书**（没有就建一本，名为「卡名 · 存档」）。条目常驻、角色定义前、顺序 100；同名条目已存在就更新，不会新建第二本，也不会重复加条目。酒馆版本不支持聊天世界书时，**退回写入角色主世界书**，并在页面上明确告诉玩家（ADR 0012）。
2. **填入开场信息**：输入框是空的就填入并发送；输入框里已经有内容时**不覆盖**，改为复制到剪贴板并提示玩家自己粘贴。
3. **写入初始变量**（`初始变量: true` 时）：按每个字段的 `写入:` 路径写进 MVU 变量。写不进去只提示，不中断前两步，进入游戏后让模型重算一次即可。

第 1、2 步出错时停在错误面板，玩家已填的内容都留在页面上，可以重试；已经发出去的开场信息不会再发一遍。

## 硬规则

- **不收集 API Key**：不设任何要玩家填 Key 的字段，也不请求外部接口。骨架的创角页没有「AI 帮写」；设计书一定要时，说明只能走酒馆当前的模型连接（`generateRaw`），并且要按通用规则的「手写前端」另写，先和用户确认。
- 每一步都能回退，已填的内容不丢（骨架保证）；你要保证步骤与字段和设计书一致。
- 写入变量的路径都在变量表里，不在表里是 `variable-binding` 错误；不在这里定义变量字段，也不改世界书里的其他条目。
- 同人卡：可选的原作人物只列资料支撑得住的；玩家也可以建原创角色。
- 模板与开场信息里的 `{键}` 必须是某个字段的 `键`，写错的占位会变成空白。

## 拒绝

- 设计书没有写创角步骤或字段：停下，请用户回规划补。
- 变量表还没写或没生成而创角页要写初始变量：停下，先去脚本 · 变量结构。
- 要求在卡里填 API Key 或接外部模型接口：拒绝，说明规则。

## 自检

- `findRegex` 能命中开场白里的 `<start>` 块。
- `card_check` 没有 `sheet-invalid`、`variable-binding`，也没有别的错误。
- 【本地预览】里从第一步走到核对清单并提交：「将写入」列出聊天世界书、输入框、变量三条，内容与模板和 `写入:` 路径对得上。
- 自定义开局里写的一句话，出现在「将写入」的世界书条目与开场信息的末尾。
- 预览切到 375 档：步骤条不横向滚动，每个字段都能填。
- 页面里没有任何 Key 输入框。

## 报错回路

- 骨架自带错误面板：写明出错的步骤（渲染或提交）与错误信息，带【复制报错】按钮，并把玩家已填的内容保留在页面上；控制台日志以 `[卡名·创角页]` 开头。
- 交付时附 F12 排错步骤，以及「写入失败时怎么手动补」的说明：把核对清单里的内容手动加进聊天世界书、手动粘贴开场信息。

## 交付

按通用规则的交付格式回复：写了哪条正则、创角步骤、写入了哪本世界书的哪个条目与哪些变量、自检结果、下一步，并提醒用户点【标记完成】。
