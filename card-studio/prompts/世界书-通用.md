## 世界书通用规则

本节适用于世界书板块的每个分区。下面还有本分区的专用规则，两者冲突时以专用规则为准。

### 条目由两个文件组成

一条世界书条目就是一个组件，落在卡项目里的两个文件上：

- `世界书/<分区>/<顺序>-<名称>.md`：条目正文，由你写。
- `世界书/<分区>/<顺序>-<名称>.json`：条目参数，由应用维护。你只在需要时改 `key`（关键词）和 `comment`（条目名），其余字段不要动。

**uid 只能由应用分配**：需要新条目时调用工具 `card_new_component`，它会分配 uid、按本分区填好默认参数、建好这两个文件，并把路径告诉你。不要自己编 uid，也不要复制别人的参数文件来新建条目——拼装检查会把这两种情况报成错误。

工具：

- `card_new_component`：新建一个组件。参数 `name`（条目名）、可选 `keys`（关键词数组）、可选 `section`（默认为当前分区）、可选 `order`。
- `card_check`：跑一次拼装检查，读回错误、警告和常驻预算。交付前跑一次。

### 正文写法

- 除变量和正文格式两个分区外，条目正文用 `<条目名>` 开头、`</条目名>` 结尾包住，中间只写这一个主题的内容。开头写成 `</条目名>` 是常见错误，拼装检查会报错。
- 用 `{{user}}` 指代玩家，不要写玩家的真名。
- 正文里不写章节号、页码、出处说明，也不写「资料未载」这类标记。资料缺口记进出处索引（人设、剧情），或在交付时说明。
- 一条只讲一件事。条目之间不要互相重复大段内容。

### 参数与顺序

应用按下表给出默认参数，你通常不需要改：

| 分区 | 触发 | 位置 | 顺序 |
| --- | --- | --- | --- |
| 正文格式 | 常驻 | @深度 0 | 0 |
| 叙事规则 | 常驻 | 角色定义前 | 1–9 |
| 总览（人物总览、地点总览） | 常驻 | 角色定义前 | 10–14 |
| 标题剧情索引 | 常驻 | 角色定义前 | 15–19 |
| 设定（世界段） | 常驻 | 角色定义前 | 20–49 |
| 核心设定 | 常驻 | 角色定义前 | 50 |
| 设定（其余） | 关键词 | 角色定义前 | 51–99 |
| 人物 | 关键词 | 角色定义前 | 100 |
| 剧情 | 关键词 | @深度 4 | 300 起，按时间递增 |
| 初始变量 | 关闭 | 角色定义前 | 1002 |
| 变量列表 / 变量规则 / 变量输出格式 | 常驻 | 角色定义前 | 9994 / 9995 / 9996 |

统一参数（应用已经填好）：双向防递归开启、不用次级关键词、概率 100。

### 关键词

- 设定、组织、地点、事件：2–3 个精准词。
- 人物：本名，加常用译名或昵称，最多 5 个。
- 剧情：篇章名，加上这一条涉及的每一个完整日期。
- **禁止使用多人共用的称号**（例如「九神将」「王选候补」这类头衔）。一个称号会同时触发一串人物，把上下文撑爆。
- 拼装检查会报出撞词：两条启用的条目共用同一个关键词时给警告，自己判断是否该改。

### 开工顺序

1. 读 `设计书.md`，确认本次要写什么、写多少、有没有被列进「不做清单」。
2. 读 `资料/索引.md`，按任务找到相关分章再精读，不整本通读。
3. 读已经写好的上游组件（例如写人物前先读人物模板和人物总览）。
4. 需要酒馆机制的事实时，读知识库对应篇章；需要写法参考时，读内置的 Re0 范例库 `re0/README.md`。

### 自检（每次交付前）

- 包裹标签成对，条目名与 `comment` 一致。
- 关键词符合本分区规则，没有共用称号。
- 正文没有出处、章节号和格式外的标记。
- 与设计书一致；没有写进「不做清单」的内容。
- 跑过 `card_check`，错误为 0；警告逐条说明是修掉了还是有意保留。
