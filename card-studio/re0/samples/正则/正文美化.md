## 结构

```
<style>   设计令牌（--re0v2-*）、阅读主题、字号与字体档位、手机断点
<body>    挂载点
<script>
  词法层   tokenizeInlineText 等：把正文切成旁白、对白、强调、链接等片段
  解析层   parsePackedContentEnvelope：按固定顺序读 <story> → <time> → <now_plot>
  设置层   readReadingSettings / writeReadingSettings：阅读主题、字号、首行缩进，存在 localStorage
  人物层   resolveCharacter：人名 → 颜色与头像（头像只认用户覆盖的链接）
  渲染层   element / button / appendInline：只用 textContent 写文本
  兜底层   renderFallback：解析失败时显示可读原文
```

## 关键片段二：解析失败时显示可读原文

```js
function renderFallback(documentRef, parsed, source) {
  const fallback = element(documentRef, 'section', 're0v2-fallback');
  fallback.setAttribute('role', 'alert');
  fallback.append(
    element(documentRef, 'p', 're0v2-fallback__mark', '正文协议'),
    element(documentRef, 'h1', '', '正文协议尚未成形'),
    element(documentRef, 'p', '', parsed.errors?.[0]?.message || '请等待生成完成，或检查正文输出格式。'),
    element(documentRef, 'pre', '', String(source ?? '').slice(0, 4000)),
  );
  return fallback;
}
```

原文放在 `<pre>` 里用 `textContent` 写入，不会被当成 HTML 执行；截断到 4000 字，防止极长的坏输出拖垮页面。

## 可以学的

- 正文格式 ↔ 解析器一一对应；卷号、篇章、时间属性都拿白名单核对。
- 流式中间态（没有 `</now_plot>`）单独处理，生成过程中也能看。
- 全部用 `textContent` 写文本，没有 `innerHTML` 拼接。
- 阅读设置（主题、字号、缩进）存在本地，玩家改一次全卡生效。
- 人物头像只认用户提供的链接，没有就用首字与按名字算出的颜色。

## 不要学的

- `minDepth: 0` + `maxDepth: null` 等于每一楼都渲染；新卡按设计书限制到最近 10 楼，更早的楼层用轻量正则去标签。
- 13 万字符的单文件：新卡控制在能读懂的规模，重复的样式与工具函数不要复制三份（原卡的完整版、极简版、变体各带一套）。
- 外部字体：原卡引了在线字体，新卡一律系统字体栈。
