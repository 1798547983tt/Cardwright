## 结构

```
<!DOCTYPE html>
  <style>  ——  设计令牌（--re0v2-*）、布局、分页、响应式
  <body>   ——  折叠条 + 展开面板（分页签）+ 错误区
  <script> ——  作用域探测 → 等 MVU → 读变量 → 规范化 → 渲染 → 订阅更新
```

脚本部分分四层：**取数**（等待与读取）、**规范化**（字段缺失兜底）、**渲染**（纯函数产出 DOM）、**订阅**（更新事件到来时重画）。层与层之间只传数据，方便单独排查。

## 关键片段：等 MVU 就绪，带超时

```js
async ready(timeoutMs = 2500) {
  if (scopeHasRuntime(scope)) return this.probe();
  const wait = callable('waitGlobalInitialized');
  if (!wait) return this.probe();
  let timer;
  try {
    await Promise.race([
      Promise.resolve(wait('Mvu')),
      new Promise(resolve => { timer = setTimeout(resolve, Math.max(0, timeoutMs)); }),
    ]);
  } catch {}
  clearTimeout(timer);
  return this.probe();
}
```

三件事值得学：

1. 先看接口存不存在（`callable('waitGlobalInitialized')`），不存在就降级，不直接崩。
2. `Promise.race` 加超时，酒馆版本不对或 MVU 没装时不会一直卡在加载态。
3. 等完之后再 `probe()` 一次确认，而不是假设等到了。

## 已知问题：没有限制楼层

`minDepth` 与 `maxDepth` 都是 `null`，意味着**每一条命中的 AI 回复都会渲染一次状态栏**。长对话里几十个 iframe 同时存在，明显变慢。

新卡要改成只在最新一楼渲染：

```js
if (getCurrentMessageId() !== getLastMessageId()) return;   // 或者用 maxDepth: 0
```

两种做法都要在真实酒馆里验证后再定（见知识库 `30-正则与渲染管线.md`）。

## 可以学的

- 占位符方案：正文格式写占位符，正则只负责把它换成界面。两边职责清楚。
- 字段缺失时显示「未知」而不是报错。
- 设计令牌集中在 `:root` 里（`--re0v2-*` 前缀避免和酒馆自身样式打架）。
- 折叠态只有一行关键信息，展开后才分页。

## 不要学的

- 不限楼层渲染。
- 近 20 万字符的替换内容：新卡应当把状态栏做薄，必要时把复杂逻辑挪进脚本。
- 依赖外部字体与图床（原卡用了 Google Fonts 与 GitHub raw，国内网络下会失败）。
