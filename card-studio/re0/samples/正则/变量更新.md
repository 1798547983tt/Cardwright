## 最值得学的一点：不用脚本

两条回执都是纯 HTML + CSS：`<section>` 里一个 `<details>`，`<summary>` 是折叠时的一行，展开后是两个 `<pre>`。没有 `<script>`，所以它不会变成 iframe，而是走酒馆自己的 Markdown 与净化流程——体积小、渲染快、几乎不会坏。

## 完成回执的查找模式

```
/<UpdateVariable>\s*<(?:[Aa]nalysis|[Aa]nalyze)>\s*((?:(?!<|\x60{3}|~{3})[\s\S])*?)\s*<\/(?:[Aa]nalysis|[Aa]nalyze)>\s*<JSONPatch>\s*(\[(?:(?!<|\x60{3}|~{3})[\s\S])*?\])\s*<\/JSONPatch>\s*<\/UpdateVariable>/g
```

- 第 1 组取 Analysis，第 2 组取 JSON Patch（必须以 `[` 开头、`]` 结尾）。
- 两个组都用 `(?:(?!<|\x60{3}|~{3})[\s\S])*?`：**里面不许出现 `<` 和代码围栏**。模型要是在分析里写了标签，整条不匹配、原文照常显示——这是在正则层面挡住了 HTML 注入。
- 同时容忍 `Analysis` / `analysis` / `Analyze` 几种写法。

## 替换内容的骨架

```html
<section data-re0-vu-root data-re0-vu-state="complete" aria-label="变量更新回执：世界线记录已闭合">
  <details class="re0-vu-receipt">
    <summary class="re0-vu-summary">
      <span class="re0-vu-heading">
        <span class="re0-vu-brand">Re:0 · 变量记录</span>
        <strong class="re0-vu-title">世界线记录已闭合</strong>
        <span class="re0-vu-subtitle">本轮更新依据与补丁已完整生成</span>
      </span>
    </summary>
    <pre class="re0-vu-source re0-vu-analysis-source" aria-label="本轮变量更新依据">$1</pre>
    <pre class="re0-vu-source re0-vu-patch-source" aria-label="原始 JSON Patch">$2</pre>
  </details>
  <style>/* re0-vu-* 前缀的样式 */</style>
</section>
```

「更新中」那条结构相同，只是 `data-re0-vu-state="pending"`、`<details>` 带 `aria-busy="true"`，不放捕获内容。

## 可以学的

- 能不用脚本就不用：回执只需要折叠与展示，`<details>` 足够。
- 捕获组排除 `<` 与代码围栏，防注入。
- 两条正则一条管未闭合、一条管闭合，互不重叠。
- 样式类名统一带前缀（`re0-vu-`），不和酒馆或其他正则打架。
- 语义属性（`aria-label`、`aria-busy`、`role`）齐全。

## 不要学的

- `minDepth` / `maxDepth` 都不限：配合固定正则「只发送最新 3 楼的变量更新」时，显示层仍会在每一楼都展开一张回执。新卡可以按设计书限制显示楼层。
