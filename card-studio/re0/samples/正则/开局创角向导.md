## 流程

五步：身份 → 出身 → 内心 → 羁绊 → 启程。启程页带核对清单。每一步的选择只进**草稿**，只有最后提交时才写世界书、填输入框。

## 关键片段一：找接口时先确认它存在

```js
function worldbookApiHost() {
  for (const owner of candidateWorldbookOwners()) {
    try {
      if (typeof owner.getCharWorldbookNames === 'function' && typeof owner.updateWorldbookWith === 'function') return owner;
    } catch {}
  }
  return null;
}
```

在当前 iframe、父窗口里依次找，找不到就返回 `null`，由调用方给出人话提示，而不是报 `undefined is not a function`。

## 关键片段二：写世界书——更新受管条目，不动其他条目

```js
async function writeInitialWorldbook(draft) {
  const api = worldbookApiHost();
  if (!api) throw new Error('未检测到 Tavern Helper 世界书 API，无法写入初始人物设定。');
  const bindings = await Promise.resolve(api.getCharWorldbookNames('current'));
  const worldbookName = bindings?.primary;
  if (!worldbookName) throw new Error('当前角色没有绑定主世界书，无法写入初始人物设定。');
  const content = buildInitialWorldbookContent(draft);
  const written = await api.updateWorldbookWith(worldbookName, entries => {
    if (!Array.isArray(entries)) throw new Error('世界书条目格式异常，已停止写入以保护原有内容。');
    const managed = entries.find(isInitialWorldbookEntry) || null;
    return upsertInitialWorldbookEntry(entries, makeInitialWorldbookEntry(content, managed));
  }, { render: 'debounced' });
  if (!Array.isArray(written) || !written.some(isInitialWorldbookEntry)) {
    throw new Error('世界书写入后未找到初始人物设定条目。');
  }
}
```

- 受管条目靠 `extra.source` / `extra.kind` 标记识别：重复创角是**更新**这一条，不会越写越多。
- 写之前检查条目数组的形态，不对就停，保护原有内容。
- 写完**读回确认**条目确实在里面。

## 关键片段三：填输入框，不行就复制

```js
function findTavernComposer() {
  for (const hostDocument of candidateHostDocuments()) {
    const textarea = hostDocument.querySelector('#send_textarea, textarea[data-i18n="Type a message"], textarea[placeholder*="message" i]');
    if (!textarea) continue;
    const sendButton = hostDocument.querySelector('#send_but, button[title*="Send" i], button[aria-label*="Send" i]');
    return { textarea, sendButton };
  }
  return null;
}
```

找不到输入框、或者输入框里已经有玩家自己的内容时，改用剪贴板（`navigator.clipboard.writeText`，不可用时退回隐藏 textarea + `execCommand('copy')`），并提示玩家自己粘贴。

## 和本规格不同的地方（新卡按本规格做）

| Re0 的做法 | 本规格 |
| --- | --- |
| 写进**角色主世界书** | 写进**当前聊天的聊天世界书**，世界书名「卡名 · 存档名」；酒馆不支持聊天世界书时才退回主世界书，并在页面上提示（ADR 0012） |
| AI 灵感支持三种来源：酒馆 `generateRaw`、**独立 API（卡里填 Key）**、离线灵感 | **只保留酒馆当前连接**（`generateRaw`）。卡里不出现任何 Key 输入框 |
| 草稿包可以导出 | 不做 |

## 可以学的

- 草稿与提交分开，提交是一个事务：写世界书 → 读回确认 → 填输入框。
- 受管条目带标记，重复提交是更新而不是新增。
- 每个外部接口先探测再调用，缺失时给人话提示。
- 输入框有内容时不覆盖。

## 不要学的

- 独立 API 与 Key 输入框。
- 25 万字符的单文件：新卡的创角页只做设计书列出的步骤。
- 不限楼层：开场白只在第一楼，但 `[1,2]` 加不限深度意味着玩家在消息里手写 `<start>` 也会被渲染。
