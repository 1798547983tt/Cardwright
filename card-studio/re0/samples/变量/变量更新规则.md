# [mvu_update]变量更新规则（Re0 范例）

> 原卡参数：常驻 ｜ 角色定义前 ｜ 顺序 9995 ｜ uid 1 ｜ 4918 字
> 关键词：（无）

变量条目：更新时机、Patch 约定、不变量与输出格式的写法样本。

```
---
变量更新规则:
  总则:
    - 变量只记录当前可变状态；原作资料、角色知识、静态性格与背景由世界书负责，不写入变量。
    - 只根据本轮正文中已经发生且有明确因果依据的事实更新。不得为了显得活跃而随机改变数值、关系或事件。
    - 每次回复都检查所有顶层对象；没有变化的类别只在 Analysis 写“无变化”，不生成无意义 Patch。
    - 主角档案在初始化后锁定，聊天期间不得换成另一名角色。主角可以是任意原作人物或原创角色。
    - 菜月昴无论是否为主角，在当前世界中必须恰好保留一份动态状态：若他是主角，只存在于主角档案；若不是，则存在于关系.人物.菜月昴。
    - 数值仪表只表达叙事状态，不是原作官方属性，也不单独决定行动或战斗结果。
    - 存档快照、世界重启次数、轮回分支由脚本维护，模型只拨动轮回.指令下的开关，不得自行改写。

  Patch约定:
    - 只使用 add、replace、remove。
    - path 必须以 / 开头并严格对应中文变量路径；JSON Pointer 中的 ~ 编码为 ~0，/ 编码为 ~1。
    - add 用于新建对象、记录或数组项；新建记录时一次 add 完整对象，字段齐全。
    - replace 只用于已经存在的路径；不得对不存在的路径使用 replace。
    - remove 只用于确认存在且应清理的记录。
    - 0~100 仪表写纯数字并保持范围；好感范围 -100~100；禁止附加百分号或单位。
    - 布尔字段只写 true 或 false。

  初始化:
    - 当主角档案.主角锁定为 false 时，必须从用户开局信息一次性初始化所有已知状态；未知内容保留默认值，禁止猜测。
    - 初始化主角档案的姓名、角色类型、性别、年龄阶段、种族、身份、阵营、容貌、衣着、生存状态、状态仪表、战力等阶、能力与当前目标。
    - 初始化世界的规范日期、时段、时间层、地点、环境、危机等级、动向与势力态势。
    - 初始化关系、事件、线索和资产中与开局直接相关的条目，不加载全部人物资料。
    - 若主角不是菜月昴，必须在关系.人物中 add 完整的菜月昴条目；若主角是菜月昴，不得重复新增。
    - 初始化完成后在同一 Patch 末尾 replace 主角档案.主角锁定为 true。首份存档点由脚本在锁定时自动建立，模型不写快照。

  世界:
    当前时间:
      - 规范日期使用项目魔女历；每年12月、每月30天。没有原作绝对日期时使用编辑演算或历史估算标记。
      - 时段只使用黎明、清晨、上午、正午、下午、傍晚、夜间、深夜、凌晨、时段未详，不擅自推算分钟。
      - 时间层只能是主线、轮回分支、历史回溯、试炼幻境。历史回溯和试炼幻境不推进主线世界时间。
      - 轮回分支由脚本在死亡回归后改写为 B01、B02……模型不改。
    当前地点:
      - 按国家、地区、场所、具体位置分别记录；只在人物实际移动或场景明确切换后更新。
    环境:
      - 天气、光照或现场条件发生可感知变化时更新；描述只写会影响当前行动的环境状态。
    危机等级:
      - 只能是无、低、中、高、灾难；根据当前直接威胁更新，不因远方传闻自动提高。
    动向:
      - 最多保留5条与当前剧情有关的长期事件；每条为 {标题, 阶段, 类型, 地点, 描述}，键使用稳定事件ID。
      - 阶段只能按起→承→转→合推进。进入合并记录结果后，从动向移除；需要追踪结果时写入事件.近期记录。
    势力态势:
      - 只记录会影响当前剧情的势力；每条为 {立场, 状态, 描述}，键使用势力规范名；立场改变必须有事件依据。

  主角档案:
    - 主角锁定为 true 后，姓名与角色类型不得改变；化名只写入身份或当前形态，不更换主角。
    - 生存状态只能是存活、濒死、昏迷、失踪、生死未卜、死亡。
    - 生命、体力、魔力、精神稳定、门负荷、魔女余香均为0~100；仅在受伤、行动、施术、休息、治疗或明确精神冲击时更新。
    - 生命为0不自动等于死亡。只有正文明确确认实际死亡，才把生存状态写为死亡。
    - 伤势条目为 {部位, 程度, 描述}，程度只能是轻微、轻度、中度、重度、致命；异常状态条目为 {类型, 剩余表现, 描述}。两者键使用稳定ID，获得时 add 完整对象，康复或解除时 remove。
    - 战力等阶记录当前形态下的阶数、位阶（上位、下位、未定、未知）、可战状态（可战、受限、无法战斗、未知）和生效条件；形态、场地、能力封锁或严重伤势变化时才更新。
    - 能力按加护、权能、魔法、精灵术、种族能力、武技、一般技能分类；每项为 {状态, 可用性, 消耗或冷却, 描述}，可用性只能是可用、受限、冷却中、不可用、已失去、未知。
    - 当前目标只记录当前明确行动目标；当前行动记录本回合正在做的事；目标完成、失败或放弃时更新或清空。
    - 心声为一句话，写主角此刻真实想法，可以与言行相反；只有正文明确写出主角的心理活动时才更新，不得替玩家发明想法。

  关系:
    - 关系只有一个容器 关系.人物，键使用人物规范姓名。每条完整字段为 {关系类型, 身份, 阵营, 立场, 关系阶段, 好感, 信任, 契约状态, 对主角称呼, 在场, 当前地点, 最后出场, 心声, 生存状态, 生命, 体力, 魔力, 精神稳定, 伤势, 异常状态, 当前形态, 战力等阶, 当前目标, 当前行动}。新建人物必须一次 add 完整对象。
    - 关系类型只能是一般、伴侣、契约伙伴。伴侣必须由叙事明确确认，不得把普通同伴或单向好感写成伴侣；契约伙伴用于精灵、契约对象和长期绑定伙伴，并同时填写契约状态。改变类型只 replace 关系类型字段，不迁移条目。
    - 立场只能是友方、中立、敌对、未知；关系阶段为简短文本。
    - 好感范围-100~100，信任范围0~100；只有明确互动或重大事件才能改变，单次常规变化保持克制。
    - 对主角称呼记录该人物当面称呼主角的方式；首次登场时写入，正文明确改口时才修改。
    - 在场表示该人物此刻与主角同处一个场景、可被感知或互动。场景切换、人物到达或离开时逐人核对；由 true 变为 false 的同一 Patch 中，写入最后出场的 {日期, 地点}。
    - 当前地点记录人物当前所在；不在场且去向不明时写“未知”。
    - 心声为一句话，写该人物此刻的真实想法，可以与其言行相反；只更新本回合在场人物的心声，不在场人物不更新。
    - 人物只追踪近期登场、同行、失踪或会影响当前事件的人物，不加载完整人物档案。不追踪人物能力清单，能力资料由世界书负责。
    - 人物离场不等于删除。仅在长期无关且没有未完事件引用时 remove；菜月昴永不因离场清理。

  轮回:
    - 轮回.世界重启次数、轮回.存档点.有效、快照ID、创建时间、地点由脚本维护，模型不得 replace。
    - 推进存档点只在叙事明确表明死亡回归锚点已经推进时进行：replace /轮回/指令/推进存档点 为 true，并 replace /轮回/存档点/摘要 为一句话描述锚点。普通换场、睡眠、闲聊或模型判断不得推进。
    - 只有当前运行世界中的菜月昴被正文明确确认实际死亡，才触发死亡回归。濒死、昏迷、失踪、生死未卜、幻觉、替身死亡、试炼影像、历史回溯或未落地假设都不触发。
    - 一次死亡是一个事件。死亡ID按顺序写作 D01、D02……同一死亡无论被分段描述多少次，只处理一次。
    - 触发死亡回归时，在同一个 JSONPatch 中完成且只做以下三件事：
      1. add /轮回/菜月昴死亡记录/{死亡ID}，内容为 {重启编号, 日期与时段, 地点, 直接原因, 经过与最后行动, 相关人物, 遗留情报}；重启编号为当前世界重启次数加一，相关人物为字符串数组，遗留情报为菜月昴亲历的情报字符串数组，最多5条。
      2. replace /轮回/最近一次死亡回归/死亡ID 与 /轮回/最近一次死亡回归/直接原因。
      3. replace /轮回/指令/死亡回归 为 true。
    - 死亡回归回合不得再修改世界、主角档案、关系、事件、线索、资产中的任何字段；脚本会用存档快照恢复这六个容器、增加世界重启次数、改写轮回分支并清空当前战斗。
    - 同一回合不得同时把推进存档点和死亡回归都设为 true。
    - 死亡回归后，除菜月昴外其他人物默认不保留失败轮回的记忆。

  事件与线索:
    - 进行中事件条目为 {标题, 类型, 阶段, 状态, 地点, 参与者, 目标, 描述}，键使用稳定事件ID，参与者为人物姓名数组；同一因果链使用同一事件ID。
    - 事件结束后从进行中 remove，并 add 到近期记录，条目为 {标题, 结果, 规范日期, 参与者, 描述}。近期记录最多12条，超出时 remove 最旧的一条。
    - 当前线索条目为 {标题, 状态, 关联事件, 描述, 下一步}，最多30条；未解决或正在使用的线索不得因裁剪删除。
    - 未解问题为字符串数组，记录尚未解答的关键疑问。

  当前战斗:
    - 战斗开始时 replace /事件/当前战斗 的各字段：进行中 true、非空战斗ID、轮数、阶段“准备”、参战者与先攻顺序为同一批稳定ID字符串数组、当前行动者、行动额度按参战者ID记录 {主行动, 移动, 防御反应}；距离、掩体、持续效果和濒死计数按参战者ID记录。
    - 每次检定只 replace /事件/当前战斗/最近一次检定 为 {检定类型, 骰面, 目标DC, 修正, 总值, 结果等级, 目标, 时间}；不得写入骰池、随机种子、完整战斗日志或历史记录。
    - 战斗中的生命、体力、魔力、精神稳定和伤势仍回写对应的主角档案或关系人物长期字段；行动额度和临时效果只留在当前战斗。
    - 战斗结束时先将最终生命、资源与伤势回写长期字段，再把当前战斗恢复为：进行中 false、战斗ID ''、轮数 0、阶段 ''、参战者 []、先攻顺序 []、当前行动者 ''、行动额度 {}、距离 {}、掩体 {}、持续效果 {}、濒死计数 {}、最近一次检定 null。

  资产:
    - 货币条目为 {数量, 持有者, 存放位置}；物品条目为 {名称, 数量, 持有者, 存放位置, 描述}；装备条目为 {名称, 持有者, 装备状态, 损耗, 当前效果}；据点与存放条目为 {名称, 位置, 控制者, 状态}。
    - 获得新资产时 add 完整对象；数量或状态变化时 replace 已有子字段；确认失去且数量为0时 remove。
    - 资产转移必须同时更新持有者与存放位置，不能在两个位置重复持有。

  清理与不变量:
    - 动向最多5条，近期记录最多12条，当前线索最多30条，单次死亡遗留情报最多5条。
    - 主角档案只有一个且不可切换；菜月昴动态状态恰好一份；死亡ID不可重复计数。
    - 动态记录的键使用稳定ID或规范姓名；显示名称变化不应破坏引用路径。
    - 不删除进行中事件、未解问题或死亡记录。
    - 持久化状态永远不保存骰池、完整战斗日志或检定历史；UpdateVariable 永远是每次回复的最后一个块。
```
