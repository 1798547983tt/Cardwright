# [mvu_update]变量输出格式（Re0 范例）

> 原卡参数：常驻 ｜ 角色定义前 ｜ 顺序 9996 ｜ uid 2 ｜ 1040 字
> 关键词：（无）

变量条目：更新时机、Patch 约定、不变量与输出格式的写法样本。

```
---
变量输出格式:
  rule:
    - 每次回复末尾输出且只输出一个 UpdateVariable 块；正文先完成，变量块置于最后。
    - Analysis 按七条逐项写可核对的更新依据；没有变化的条目只写“无变化”，不输出资料考据、角色知识或隐藏推理。
    - JSONPatch 必须是合法 JSON 数组，只允许 add、replace、remove。
    - 每个 path 必须以 / 开头，严格对应中文变量路径，并遵守 JSON Pointer 转义。
    - 新增动态对象时 add 完整对象；只有路径已存在时才能 replace。
    - 没有状态变化时，JSONPatch 输出空数组 []，不得为了满足格式制造变化。
    - 所有数值保持规定范围并使用纯数字；布尔只写 true 或 false。
    - 首次初始化必须完整处理已知的主角档案、世界、关系、事件、线索与资产，并在末尾把主角锁定改为 true；未知信息保留默认值。
    - 确认菜月昴实际死亡的回合，只写死亡记录、最近一次死亡回归与死亡回归开关三项，不再改动其他容器。

  format: |-
    <UpdateVariable>
    <Analysis>
    一、初始化与主角锁定：${是否需要初始化；主角是否已锁定；已锁定则不得切换。}
    二、时间·地点·环境·危机：${规范日期、时段、时间层、地点、天气、光照、危机等级、动向、势力态势是否改变。}
    三、主角状态：${生存状态、仪表、伤势、异常状态、形态、战力等阶、能力、目标、行动、心声是否改变。}
    四、关系与在场：${哪些人物在场或离场；好感、信任、关系类型、称呼、心声是否改变；是否新增或清理人物；菜月昴是否恰好一份。}
    五、事件·线索·资产：${进行中事件、近期记录、线索、未解问题、货币、物品、装备、据点是否改变。}
    六、战斗：${战斗是否开始、推进或结束；本回合检定摘要；长期字段是否回写。}
    七、死亡回归与存档点：${是否明确确认菜月昴实际死亡并排除非死亡情形；死亡ID是否已用过；是否拨动死亡回归或推进存档点。}
    </Analysis>
    <JSONPatch>
    ${只输出合法 JSON 数组；无变化时输出 []}
    </JSONPatch>
    </UpdateVariable>
```
