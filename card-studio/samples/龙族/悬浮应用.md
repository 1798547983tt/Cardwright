# 前端样本 · 龙族remake 悬浮应用

| 项目 | 值 |
| --- | --- |
| 来源 | 用户本人的角色卡《龙族remake：世界的重启》里的酒馆助手脚本「龙族小手机」，在酒馆里实际运行良好 |
| 形态 | 页面级悬浮应用：一颗可拖动的悬浮球，点开是一块仿手机的面板。对应状态栏的 `形态: floating` |
| 代码规模 | 约 7 MB / 10,906 行：内嵌的 base64 图片约 3.2 MB，生成的数据表约 2.9 MB，样式约 0.2 MB，逻辑约 0.6 MB |
| 用到的接口 | `waitGlobalInitialized`、`eventOn`、`Mvu.events`（`VARIABLE_INITIALIZED`、`VARIABLE_UPDATE_ENDED`）、`Mvu.getMvuData`、`getVariables`、`tavern_events`（`MESSAGE_RECEIVED`、`CHAT_CHANGED`、`MESSAGE_SWIPED`、`MESSAGE_EDITED`、`MESSAGE_DELETED` 等） |

这张卡的楼层里没有状态栏：变量显示在悬浮面板的主页和各个应用里。本篇只分析五件事——怎么挂到酒馆页面上、怎么保证只有一个实例、怎么跟着变量重画、怎么拖动和记位置、怎么适配窄屏。片段都是按原卡思路重写的示意，不是原卡代码。

状态栏选 `形态: floating` 时，这些由应用的前端骨架负责。本篇用来理解其中的取舍，或者在手写悬浮脚本时对照。

## 结构

```
酒馆助手脚本（运行在脚本自己的 iframe 里）
├─ 几何（纯函数）  视口规整、夹紧、贴边、面板尺寸、窄屏全屏、点击 / 拖动 / 长按判定
├─ 宿主适配        逐层找外层窗口与接口、订阅事件、读变量、读写本地存储
├─ 生命周期        单实例、pagehide 清理、清除残留节点
├─ 外壳            建节点、指针与键盘、持久化、无障碍播报
└─ 运行时          变量 → 各屏幕的数据 → 重画

酒馆页面
└─ <div id="本卡前缀-host">          挂在 documentElement 上
   └─ #shadow-root (open)
      ├─ <style>                     整份样式以字符串注入
      └─ .stage                      fixed、铺满视口、不接收指针
         ├─ 悬浮球 <button>          接收指针
         ├─ 长按快捷环 role=menu
         ├─ 手机面板 <section>        拖动条 / 屏幕 / 缩放角
         └─ aria-live 播报区
```

几何模块只接收坐标和视口、返回新坐标，不碰 DOM，可以离线测试；外壳只负责把结果写到 `style` 上。

## 关键片段一：挂到酒馆页面，Shadow DOM 隔离，只留一个实例

```js
const HOST_ID = 'mycard-float-host';             // 带本卡前缀，免得和别的卡撞名

function outerDocument() {
  let win = window;
  for (let depth = 0; depth < 12; depth += 1) {
    let parent;
    try {
      parent = win.parent;
      if (!parent || parent === win) break;
      void parent.document.documentElement;       // 跨域会抛错，停在当前层
    } catch { break; }
    win = parent;
  }
  return win.document;
}

function mount(css) {
  const doc = outerDocument();
  const old = doc.getElementById(HOST_ID);
  old?.__destroy?.();                             // 旧实例先自毁
  old?.remove();                                  // 没有销毁函数的残留节点也清掉

  const host = doc.createElement('div');
  host.id = HOST_ID;
  const shadow = host.attachShadow({ mode: 'open' });
  shadow.innerHTML = `<style>${css}</style><div class="stage"><button class="ball" type="button" aria-label="打开状态面板" aria-expanded="false"></button><section class="panel" hidden></section></div>`;
  doc.documentElement.append(host);

  const disposers = [];
  const listen = (target, type, fn, options) => {
    target?.addEventListener(type, fn, options);
    disposers.push(() => target?.removeEventListener(type, fn, options));
  };
  host.__destroy = () => { for (const stop of disposers.splice(0).reverse()) stop(); host.remove(); };
  window.addEventListener('pagehide', host.__destroy);   // 脚本关掉或重载时，外层页面上的节点不会自己消失
  return { doc, win: doc.defaultView, shadow, listen, disposers };
}
```

要点：

1. 脚本跑在自己的 iframe 里，要画到酒馆页面上，先沿 `parent` 往上走到最外层能访问的窗口。每一步都用 try/catch 试探，遇到跨域就停。
2. 单实例靠三道保险：挂载前按固定 id 找旧节点，先调它的销毁函数再移除；原卡还把清理函数挂在每个能访问到的窗口的同一个全局名上，新实例启动时先调用它，再按 id 清掉残留节点（包括失败提示按钮）；最后监听 `pagehide`，脚本被关掉或重载时自毁。原卡在有 jQuery 时用 `$(window).on` 绑定 `pagehide`，没有才用原生监听。
3. 所有监听都经过 `listen()`，登记对应的反注册函数；销毁时倒序执行，事件订阅的停止函数也放进同一个数组。
4. 初始化失败时，在页面角落放一个固定定位的按钮，写明错误，点击重试。玩家不用开控制台也能自救。

## 关键片段二：跟着变量重画

```js
const toStop = handle => (typeof handle === 'function' ? handle : () => handle?.stop?.());
let signature = '';
let epoch = 0;

function accept(stat) {
  if (!stat || typeof stat !== 'object' || !Object.keys(stat).length) return;   // 空读数不覆盖界面
  const next = JSON.stringify(stat);
  if (next === signature) return;                  // 数据没变就不重画
  signature = next;
  render(stat, { keepInput: true });               // 保住正在输入的控件：焦点、选区、滚动位置
}

async function reread() {
  const mine = ++epoch;
  let data = null;
  try { data = await Mvu.getMvuData({ type: 'message', message_id: 'latest' }); } catch { /* 读不到就保持现状 */ }
  if (mine === epoch) accept(data?.stat_data);     // 读的时候又来了更新的数据，这次作废
}

async function subscribe(disposers) {
  await waitGlobalInitialized('Mvu');              // 脚本可能比 MVU 先启动
  const fromMvu = vars => { epoch += 1; accept(vars?.stat_data); };   // 事件自带更新后的整份变量
  const handles = [
    eventOn(Mvu.events.VARIABLE_INITIALIZED, fromMvu),
    eventOn(Mvu.events.VARIABLE_UPDATE_ENDED, fromMvu),
    ...[tavern_events.MESSAGE_SWIPED, tavern_events.MESSAGE_EDITED, tavern_events.MESSAGE_DELETED].map(name => eventOn(name, reread)),
    eventOn(tavern_events.CHAT_CHANGED, () => { signature = ''; reread(); }),
  ];
  disposers.push(...handles.map(toStop));
  await reread();
}
```

要点：

- **以 MVU 事件带来的数据为准。** `VARIABLE_UPDATE_ENDED` 的回调直接拿到更新后的整份变量，取其中的 `stat_data` 就能画。原卡的经验是：有的环境里 MVU 写完变量比酒馆的消息事件晚一步，那一刻去读楼层变量会拿到旧值。所以酒馆事件（滑动、编辑、删除、收到消息）只触发一次补读，最终以 MVU 事件为准。
- 补读先试 `Mvu.getMvuData({ type: 'message', message_id: 'latest' })`，失败再退到 `getVariables`；都读不到时沿用上一次成功的数据，不清空界面。
- 签名去重：同一份数据不重画。epoch 计数：异步读数回来时，如果期间已经有更新的数据，就丢掉这次结果。
- 换聊天（`CHAT_CHANGED`）时整份重来。
- 接口按窗口逐层找：当前脚本窗口、父窗口、顶层窗口，以及它们身上的 `TavernHelper` 对象。原卡另有兜底：MVU 迟迟没就绪时，前 8 秒每 50 毫秒、之后每秒试一次绑定，绑上就停。
- 面板打开时另外每 1.2 秒补读一次，收起就停。
- 重画时保住输入：先记下当前聚焦控件的序号、名字、值和选区，换完 DOM 再还原。只有真正切换屏幕时才播放进场动画，局部刷新不播。

## 关键片段三：拖动与记位置

```js
const BALL = 56, GAP = 8, SLOP = 6, KEY = 'mycard.float.v1';   // 存储键带版本号

function frame(win) {                             // 用可见视口：键盘弹出、双指缩放时它会变
  const vv = win.visualViewport;
  return { x: vv?.offsetLeft ?? 0, y: vv?.offsetTop ?? 0, w: vv?.width ?? win.innerWidth, h: vv?.height ?? win.innerHeight };
}
function snap(pos, f) {                           // 贴到近的一边，只记「哪条边 + 高度」
  const edge = pos.x + BALL / 2 < f.x + f.w / 2 ? 'left' : 'right';
  const y = Math.min(Math.max(pos.y, f.y + GAP), f.y + f.h - BALL - GAP);
  return { edge, y, x: edge === 'left' ? f.x + GAP : f.x + f.w - BALL - GAP };
}
function remember(win, patch) {
  try {
    const old = JSON.parse(win.localStorage.getItem(KEY) || '{}');
    win.localStorage.setItem(KEY, JSON.stringify({ ...old, ...patch }));
  } catch { /* 存储不可用时照常工作，只是不记位置 */ }
}
let drag = null;
listen(ball, 'pointerdown', e => {
  if (e.button !== 0) return;
  ball.setPointerCapture(e.pointerId);
  drag = { id: e.pointerId, sx: e.clientX, sy: e.clientY, base: { ...pos }, moved: false };
});
listen(win, 'pointermove', e => {                 // 挂在窗口上：指针滑出球、跨过 shadow 边界也不断
  if (!drag || e.pointerId !== drag.id) return;
  e.preventDefault();
  const dx = e.clientX - drag.sx, dy = e.clientY - drag.sy;
  drag.moved ||= Math.hypot(dx, dy) >= SLOP;
  if (drag.moved) place({ x: drag.base.x + dx, y: drag.base.y + dy });   // place：夹进视口并写 style
}, { passive: false });
listen(win, 'pointerup', e => {
  if (!drag || e.pointerId !== drag.id) return;
  const moved = drag.moved; drag = null;
  if (!moved) return togglePanel();               // 挪动不到 6px 算点击
  pos = snap(pos, frame(win));
  place(pos);
  remember(win, { ball: { edge: pos.edge, y: pos.y } });
});
listen(win, 'pointercancel', () => { drag = null; });
```

要点：

- 按下时捕获指针，移动和松开挂在窗口上：有的浏览器跨过 Shadow DOM 边界后留不住指针捕获，挂在窗口上拖动也不会断。
- 手势判定是纯函数：移动超过 6px 算拖动；没动过、按住超过 560 毫秒算长按（弹出三个常用应用的快捷环）；其余算点击。
- **位置只记「哪条边 + 高度」。** 恢复时按当前视口重新贴边、夹紧：在电脑上拖到右边，换到手机上打开仍在右边，不会跑出屏幕。面板的位置与尺寸也记下，恢复时同样夹紧；上次是开着的，就恢复成开着。
- 存储用酒馆页面窗口的 `localStorage`，键名带版本号；读出来和原有内容合并后再写回；读写都包 try/catch，隐私模式下照常工作。
- 键盘：球是真正的 `<button>`，带 `aria-label` 和 `aria-expanded`；回车或空格开关面板，左右方向键把球换到左边或右边并保存。开关面板、展开快捷环时通过 `aria-live` 区域播报。
- 面板的拖动条（在按钮上按下不算拖动）和右下角缩放角走同一套指针逻辑；面板尺寸限制在 360–560 × 640–900，始终夹在视口内，四周留 8px。

## 关键片段四：宿主样式与窄屏

```css
:host {
  all: initial;                                   /* 不继承酒馆主题的字体、颜色、文字阴影 */
  position: fixed; left: 0; top: 0;
  width: 0; height: 0; overflow: visible;         /* 宿主节点本身不占位 */
  z-index: 2147480000;
  font-family: system-ui, "PingFang SC", "Microsoft YaHei", sans-serif;
}
.stage { position: fixed; inset: 0; pointer-events: none; }   /* 铺满视口，但不挡酒馆的点击 */
.ball, .panel { pointer-events: auto; }
.ball { position: fixed; width: 56px; height: 56px; touch-action: none; }   /* 触屏拖动时不滚动页面 */

/* 窄屏：脚本按可见视口宽度给面板打上 data-fullscreen，同时停用拖动与缩放 */
@media (max-width: 560px) {
  .panel[data-fullscreen="true"] { width: 100dvw; height: 100dvh; border-radius: 0; }
  .panel[data-fullscreen="true"] .bar { padding-top: env(safe-area-inset-top, 0px); }
  .panel[data-fullscreen="true"] .screen { padding-bottom: env(safe-area-inset-bottom, 0px); }
}
@media (max-width: 390px) { .screen { padding-inline: 10px; } }

/* 玩家选的动效档位写在宿主上 */
:host([data-motion="static"]) *,
:host([data-motion="static"]) *::before,
:host([data-motion="static"]) *::after { animation: none !important; transition-duration: .01ms !important; }
```

要点：

- 视口一律取 `visualViewport`（可见区域的宽高和偏移），不直接用 `innerWidth` 和 `innerHeight`：手机弹出键盘、双指缩放时可见区域会变小、会偏移，按它夹紧，球和面板才不会被键盘挡住。
- 重新夹紧的时机：`visualViewport` 的 resize 和 scroll、窗口的 resize，再加一个观察 `documentElement` 的 ResizeObserver。脚本窗口和酒馆页面窗口不是同一个时，两边都监听。
- 可见宽度 ≤ 560px 时面板改为全屏，让出刘海和底部手势条的安全区，并且不再响应拖动和缩放；≤ 390px 再收紧间距。更宽时面板默认贴在右上角。
- 深浅两套主题写在宿主的 `data-theme` 上，动效三档（华丽 / 精致 / 静态）写在 `data-motion` 上，样式用 `:host([data-…])` 切换。

## 可以学的

- 页面级的东西只挂一份：固定 id、旧实例自毁、`pagehide` 清理，所有监听都登记反注册函数。
- Shadow DOM 加 `:host { all: initial }`：酒馆主题和别的美化进不来，自己的样式也漏不出去。
- 舞台层 `pointer-events: none`，只有球和面板接收指针，不挡酒馆本身的操作。
- 以 MVU 事件带来的数据为准；签名去重；epoch 丢弃过期读数；读不到保留上一次；重画时保住输入。
- 位置只记「边 + 高度」，恢复时按当前视口重新贴边；存储键带版本号，读写包 try/catch。
- 几何与手势判定写成纯函数，可以离线测试。
- 面板收起时不轮询。
- 初始化失败有看得见的重试入口。

## 不要学的

- **仿手机的各种应用**：NPC 私聊和群聊（脚本直接调模型接口生成回复）、论坛、音乐播放器、本地媒体、相册、笔记、模型列表、地图、日历……状态栏只负责把变量显示出来。这些功能各自要花调用额度、占存储、要长期维护，和状态栏无关。
- **面板里的写操作**：装备库直接改 `stat_data`，还会把最近几楼的正文注入提示词。状态栏只读；改变量是机制脚本的事，往提示词里加内容是世界书和预设的事。
- **7 MB 的单个脚本**：壁纸等图片以 base64 内嵌，人设、地图、日历的生成数据也放在同一个文件里，每次打开聊天都要整份解析。状态栏脚本只放逻辑和样式。
- **外部托管的资源**：内置音乐指向外部代码托管站上的文件直链，联系人头像也接受任意外部链接。新卡不引外部图床和音频托管；头像只用用户提供的图片，没有就显示首字。
- **「减少动态效果」只做了一半**：样式里有一条全局的 `prefers-reduced-motion` 规则，把所有动画压到 0.01 毫秒；但动效档位默认是「精致」，不读系统设置，切屏的进场动画也是脚本只看档位就加上去的。新写的话，默认档位先看 `matchMedia('(prefers-reduced-motion: reduce)')`，玩家手动选的档位再覆盖它。
- 长按快捷环、缩放角这些是手机题材的需要；普通状态栏一颗球加一块面板就够了。
