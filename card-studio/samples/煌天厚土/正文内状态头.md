# 前端样本 · 煌天厚土 正文内状态头

| 参数 | 值 |
| --- | --- |
| 来源 | 用户本人的角色卡《煌天厚土》里的正则「正文美化 主」，在酒馆里实际运行良好 |
| `findRegex` | `/<content>([\s\S]*?)<\/content>/is` |
| `placement` | `[2]`（AI 输出） |
| `markdownOnly` / `promptOnly` | `true` / `false`（只改显示） |
| `minDepth` / `maxDepth` | `null` / `null`（**每一楼都渲染，这是已知问题**） |
| 替换内容规模 | 221,885 字符 / 3,338 行；样式约 10.7 万字符，脚本约 11.4 万字符 |
| 同卡配套 | 「正文美化 流」接住还没闭合的 `<content>`（生成中）；占位符 `<StatusPlaceHolderImpl/>` 由另一条正则处理掉 |
| 用到的接口 | `getCurrentMessageId`、`getVariables`、`Mvu.getMvuData`、`Mvu.events.VARIABLE_UPDATE_ENDED`、`tavern_events`（`MESSAGE_UPDATED`、`MESSAGE_SWIPED`）、`eventOn`、`eventEmit` |

这张卡的状态栏不单独占一条正则，而是正文美化文档的开头：每一楼的正文 iframe 顶部先画一个状态头，下面才是正文。对应状态栏的 `形态: header`（正文美化装配单写 `状态头: true`）。用骨架时这些由骨架负责；本篇用来理解做法，或在手写正文美化时对照。片段都是按原卡思路重写的示意，不是原卡代码。

## 结构

整份替换内容是包在 html 代码块里的一个完整文档，酒馆助手把它渲染成楼层里的 iframe：

```
<style>
  base        重置、布局、入场动画、动效分级
  modes       日 / 夜 / 茶 三套材质令牌
  statusbar   状态头：背景层、题签块、周天盘、分卷面板、断点
  text/blocks 正文、对白、区块
  books       五个「书」（题材）的色相、饰件与个别修正
<body>
  <textarea hidden>$1</textarea>   正文原文放在文本框里，不会被当成标签解析；脚本读它的 value
  <div class="root" data-book data-mode data-motion data-font data-size>
    <canvas>                       背景粒子，只铺楼层顶部一段
    <header class="status">        状态头挂点
    <main class="text">            正文
<script>
  env（找接口、读楼层变量、订阅）→ store（界面偏好）→ theme（书、模式、字体、动效）
  → svg（地景、周天盘）→ parse → render-text → statusbar → boot
```

状态头本身：

```
header.hd                  --tab-h：当前打开的卷决定整块头部的强调色
├─ .hd-bg    背景层：大字水印、按题材换形的地景 SVG、几道流光（aria-hidden）
├─ .hd-body  两列网格：左边题签块，右边周天盘（宽度 = --S）
│  ├─ 题签块  印章、竖排书脊、纪名大字、时间与地点、执念、读数图例
│  └─ 周天盘  以右下角为圆心的四分之一圆盘
│     ├─ 外环  七个卷位按钮：档案、天下、尘缘、因果、行囊、变动、设置（role=tablist）
│     ├─ 中环  四道气数弧：生命、精血、灵力、神识
│     └─ 核心  修为（粗弧 + 大数字）、道心（细弧 + 档位名）
└─ .hd-panel 分卷面板，默认收起；点卷位展开对应的卷，再点同一个就收起
```

- 卷位右上角的小数字是该卷的条目数（人物、物品、因果等）。「变动」卷只在本楼和上一楼的变量有差异时出现，它的角标是差异条数，并且高亮显示。
- 各字段旁边标 `+3`、`−2`、`新` 或 `已变`，改动过的行用一次 2.4 秒的底色高亮提示。
- 读不到变量时，头部进入空状态（加一个 `no-data` 类），不报错。

## 关键片段一：在正文文档里读本楼变量

```js
// 状态头画的是「这一楼」的快照：读本楼的消息变量，差异对比上一楼
function floorStat(id) {
  let vars = null;
  try { vars = getVariables({ type: 'message', message_id: id }); } catch { /* 这一楼还没有变量 */ }
  const stat = vars?.stat_data;
  return stat && typeof stat === 'object' && Object.keys(stat).length ? stat : null;
}
function nearestStat(from, limit = 12) {          // 首楼或还没初始化：往前找最近一楼有数据的
  for (let id = from; id >= 0 && id > from - limit; id -= 1) {
    const stat = floorStat(id);
    if (stat) return stat;
  }
  return null;
}

const here = getCurrentMessageId();               // 在楼层 iframe 里，它就是本楼的楼号
let stat = nearestStat(here);
render(stat, nearestStat(here - 1));

const refresh = debounce(() => {                  // debounce：普通的防抖工具函数
  const next = nearestStat(here);
  if (JSON.stringify(next) === JSON.stringify(stat)) return;   // 没变就不重画
  stat = next;
  render(stat, nearestStat(here - 1), { keepOpenTab: true });  // 展开着的卷保持展开
}, 150);

eventOn(tavern_events.MESSAGE_UPDATED, refresh);
eventOn(tavern_events.MESSAGE_SWIPED, refresh);
waitGlobalInitialized('Mvu').then(() => eventOn(Mvu.events.VARIABLE_UPDATE_ENDED, refresh));
for (const ms of [700, 2000, 4500]) setTimeout(refresh, ms);   // iframe 可能比变量写入先画出来
```

要点：

- **每楼的头是这一楼的快照**，不是「当前最新状态」：翻回旧楼层，看到的是那一回合的数值；差异的基准是上一楼往前最近的一份数据。
- 读变量先用 `getVariables`，拿不到再试 `Mvu.getMvuData`，参数都是 `{ type: 'message', message_id: 楼号 }`。
- 接口依次在本窗口、父窗口、顶层窗口以及它们身上的 `TavernHelper` 对象上找；都找不到就进入预览模式，改从预览页注入的示例数据取数，同一份文档在酒馆外也能预览。
- 订阅之后做 150 毫秒防抖；重读后和上一次比较，没变就不重画；重画时保住已经展开的卷。
- 另外在 0.7 秒、2 秒、4.5 秒各补读一次，接住「iframe 先画出来、MVU 后写完」的情况。

## 关键片段二：周天盘的弧与卷位

```js
// 圆心在正方形右下角，只画 180°→270° 这个象限。viewBox 固定 1000 单位，外框多大都等比缩放
const C = 1000;
const polar = (r, deg) => {
  const a = (deg * Math.PI) / 180;
  return [C + r * Math.cos(a), C + r * Math.sin(a)];
};
const arc = (r, from = 182, to = 268) => {
  const [x0, y0] = polar(r, from), [x1, y1] = polar(r, to);
  return `M${x0.toFixed(1)},${y0.toFixed(1)} A${r},${r} 0 0 1 ${x1.toFixed(1)},${y1.toFixed(1)}`;
};
const pct = v => Math.min(100, Math.max(0, Number(v) || 0));

// 四道弧：pathLength="100" 让 0–100 的数值直接当虚线长度，不用去量弧长
function gaugeArcs(vitals) {                      // vitals: [{ key: '生命', value: 62 }, …]
  return vitals.map(({ key, value }, i) => {
    const d = arc(700 - i * 36);
    return `<path class="track" d="${d}"/>`
      + `<path class="fill tone-${key}" pathLength="100" stroke-dasharray="${pct(value)} 100" d="${d}"/>`;
  }).join('');
}

// 卷位：沿外环均分角度，位置写成百分比，实际大小交给 CSS 的 --S
function tabPositions(count, ratio = 0.86, from = 186, to = 264) {
  return Array.from({ length: count }, (_, i) => {
    const deg = count > 1 ? from + (i * (to - from)) / (count - 1) : 225;
    const a = (deg * Math.PI) / 180;
    return { left: `${((1 + ratio * Math.cos(a)) * 100).toFixed(2)}%`, top: `${((1 + ratio * Math.sin(a)) * 100).toFixed(2)}%` };
  });
}

const svg = `<svg viewBox="0 0 1000 1000" preserveAspectRatio="xMaxYMax meet" aria-hidden="true">${gaugeArcs(vitals)}</svg>`;
```

要点：

- 整个盘只有一个尺寸变量 `--S`：`.dial-sq` 是贴在右下角、边长为 `--S` 的正方形，SVG 铺满它并按 1000 单位等比缩放，卷位按钮用百分比绝对定位，所以断点只改 `--S`，弧、刻度、卷位、标签一起缩放。
- 描边宽度按 1000 单位写：1000 单位画在三百多像素里，约为屏幕像素的 3 倍。
- 卷位标签算两套坐标（`--lx`/`--ly` 与更靠外的 `--lx2`/`--ly2`），小尺寸时换用外面那套，免得和卷位按钮叠在一起。
- 选中的卷在外环上画一块扇形高亮，按钮带 `aria-selected`；弧长变化有 `stroke-dasharray` 过渡。
- 刻度按题材换形（尖牙、星点、方印、水珠、细码），同一个函数按 `data-book` 分支。

## 关键片段三：三种模式的令牌

```css
/* 书（题材）只给色相数字 */
.root[data-book="a"] { --h1: 40;  --h2: 210; --h3: 350; }
.root[data-book="b"] { --h1: 260; --h2: 210; --h3: 195; }

/* 模式给材质：同一组语义令牌在三种模式里各算一遍，色相引用书的 */
.root[data-mode="night"] {
  --sat: 70%; --lum: 65%;
  --bg: hsl(var(--h1) 26% 8%);    --surface: hsl(var(--h1) 22% 13% / .8);
  --text: hsl(var(--h1) 22% 92%); --line: hsl(var(--h1) 28% 42% / .32);
  --accent: hsl(var(--h1) var(--sat) var(--lum));
  --glow: hsl(var(--h1) var(--sat) var(--lum) / .45);
}
.root[data-mode="day"] {
  --sat: 56%; --lum: 38%;
  --bg: hsl(var(--h1) 30% 95%);   --surface: hsl(var(--h1) 26% 99% / .85);
  --text: hsl(var(--h1) 22% 15%); --line: hsl(var(--h1) 22% 30% / .16);
  --accent: hsl(var(--h1) var(--sat) var(--lum));
  --glow: hsl(var(--h1) var(--sat) var(--lum) / .28);
}
.root[data-mode="tea"] {               /* 暖褐中间调：底和字固定，不跟书走；强调色仍用书的色相 */
  --sat: 45%; --lum: 42%;
  --bg: hsl(34 32% 87%);          --surface: hsl(34 34% 94% / .8);
  --text: hsl(28 28% 18%);        --line: hsl(28 28% 30% / .16);
  --accent: hsl(var(--h1) var(--sat) var(--lum));
  --glow: hsl(var(--h1) var(--sat) var(--lum) / .22);
  --radius: 16px; --lh: 2;             /* 茶还改形状：圆角更大、行距更松 */
}

/* 状态头再派生一层：当前打开的卷决定色相，整块头部跟着换色 */
.hd { --tab-h: var(--h1); --tab-c: hsl(var(--tab-h) var(--sat) var(--lum)); }

/* 动效三档 */
.root[data-motion="mid"] .deco-loop { animation: none !important; }
.root[data-motion="off"] *, .root[data-motion="off"] *::before, .root[data-motion="off"] *::after {
  animation: none !important; transition: none !important;
}
.root[data-motion="off"] canvas { display: none; }
```

要点：

- **两条互不相干的轴。** 书（题材）只给色相数字 `--h1`、`--h2`、`--h3` 和粒子颜色；模式给材质——底、面、线、字、强调、辉光这组语义令牌，在夜、日、茶里各写一遍，色相引用书的。组件只用语义令牌，所以五本书乘三种模式不用写十五套组件样式，只在个别组合上补几条修正。
- 夜：底色很深，描边带一圈辉光，题材色像从暗处透出来的光。日：浅底上叠一层细纸纹，字用深墨色，题材色只用来点缀。茶：暖褐的中间调，对比度压低，底色固定不跟题材走；另外放大圆角、放松行距、放慢入场动画。
- 纸纹用普通叠加，不用 `mix-blend-mode`。原卡的注释说明了原因：混合模式会给整层楼开一张全高的合成面，楼层一长，手机上就很重。
- 状态头再派生一层：`--tab-h` 由当前打开的卷决定，`--tab-c` 等颜色由它和模式的饱和度、明度算出，打开哪一卷整块头部就换成哪一卷的颜色。

## 关键片段四：模式与动效怎么选

```js
const DAY = /清晨|上午|正午|下午/;

function resolveMode(stat, locked) {
  if (locked && locked !== 'auto') return locked;               // 玩家锁定优先；茶只能手选
  const time = String(stat?.世界?.时间 ?? '');
  return DAY.test(time) ? 'day' : 'night';                      // 夜里的时辰和认不出的都用夜
}

function resolveMotion(locked) {
  if (locked && locked !== 'auto') return locked;               // high / mid / off
  if (matchMedia('(prefers-reduced-motion: reduce)').matches) return 'off';
  const small = Math.min(innerWidth, screen.width) < 700 || /Android|iPhone|iPad|Mobile/i.test(navigator.userAgent);
  return small ? 'mid' : 'high';
}

function applyTheme(root, stat, prefs) {
  root.dataset.mode = resolveMode(stat, prefs.mode);
  root.dataset.motion = resolveMotion(prefs.motion);
  // 按底色深浅给 color-scheme，不按模式名（原卡在这里把浅色的茶也标成了 dark）
  document.documentElement.style.colorScheme = root.dataset.mode === 'night' ? 'dark' : 'light';
}
```

要点：模式跟着剧情走——变量里的时辰落在白天就用日，否则用夜；玩家在「设置」卷里锁定的模式优先。每次重画都重新判断，所以剧情从下午进入黄昏，下一楼的头就换成夜。

### 断点

| 宽度 | 状态头的变化 |
| --- | --- |
| > 860px | 两列：题签在左，周天盘在右，`--S: 340px` |
| ≤ 860px | 盘缩到 `--S: 300px`，水印字和纪名缩小；各卷里的多列网格改单列 |
| ≤ 600px | 单列：题签在上，周天盘在下并贴右（`--S: 270px`）；卷位标签换外圈坐标；竖排书脊隐藏；地点只留最后两级，前面用省略号（`:has()` 判断级数）；执念压成一行省略；工具按钮移到盘左侧竖排 |
| ≤ 480px | 根容器内边距收紧 |

正文和区块另有 900px、700px、560px 几档，和状态头互不影响。

### 动效三档

| 档位 | 什么时候用 | 做了什么 |
| --- | --- | --- |
| `high` | 自动档下的桌面 | 全部动效：入场、流光、星轨、粒子画布 |
| `mid` | 自动档下的窄屏或移动设备 | 停掉循环装饰（星轨转动、流光、扫描线等），粒子数量减到一半以下 |
| `off` | 系统开了「减少动态效果」，或玩家手选 | 所有动画和过渡都关掉，粒子画布不显示 |

粒子画布另外做了节流：离开视口（IntersectionObserver）或页面切到后台（`visibilitychange`）就停帧；像素比最高 1.5，窄屏固定为 1；只铺楼层顶部最多 1600px，底边渐隐。

## 可以学的

- 头和正文在同一个文档里：共用一套令牌和字体，风格不会打架。
- 每楼的头是本楼快照，再和上一楼比出差异：「变动」卷和字段旁的增减标记，让玩家一眼看出这回合变了什么。
- 周天盘只有一个尺寸变量 `--S`，SVG 用固定 viewBox 等比缩放，卷位用百分比定位，断点只改 `--S`。
- `pathLength="100"`：0–100 的数值直接当虚线长度。
- 书与模式两条轴，组件只认语义令牌；茶模式连形状令牌（圆角、行距）一起换。
- 动效三档，自动档跟着系统设置和设备走；画布离屏、切到后台就停。
- 界面偏好改了以后广播一个自定义事件（`eventEmit`），其他楼层的 iframe 收到就重读偏好、重画，跳过自己发出的那一条。
- 生成中交给另一条轻量正则：没闭合的 `<content>` 只显示一个「落笔中」的简单框，闭合后才由主正则画全套，生成过程中不用反复跑重脚本。

## 不要学的

- **外部字体**：脚本启动时往文档里插 `<link>`，依次试一个 Google 字体的国内镜像和官方源，以及一套开源楷体字体的几个 CDN 镜像，失败就换下一个。每楼的 iframe 各发一轮请求；网络不好时字体晚到、版面跳一下，离线时直接退回系统字体。新卡一律用系统字体栈，楷、宋、黑各自列系统自带的字体，不引任何字体服务。
- **不限楼层**：`minDepth` 和 `maxDepth` 都是 `null`，每一楼都画一个完整的状态头和一块粒子画布。新卡按设计书只渲染最近 N 楼，状态头只在最新一楼展开。
- **状态头里有写操作**：设置和头像写进酒馆全局变量；人物卷里可以「删除存档人物」，直接改本楼变量。状态栏只读；界面偏好可以存在浏览器本地，改变量交给机制脚本。
- **MVU 没就绪就不订阅**：原卡在 iframe 启动的那一刻去取 MVU 的事件名，取不到就不订阅了，只剩三次定时补读。应当先等 `waitGlobalInitialized('Mvu')` 再订阅，如片段一。
- **茶模式的 `color-scheme`**：只有日模式标成 `light`，茶模式底色是浅的，却被标成 `dark`，原生控件和滚动条会按深色画。按底色深浅给，如片段四。
- **自动动效档只在重画时判断**：系统设置改了，要等下一次重画才生效。新写的话监听 `matchMedia('(prefers-reduced-motion: reduce)')` 的 `change` 事件。
- **22 万字符的单文件**：五本书乘三种模式的修正规则层层叠加，改一处要查好几处。新卡用骨架，自定义只动令牌。
